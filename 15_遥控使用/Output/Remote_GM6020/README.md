# Remote_GM6020 工程

富斯 FS-iA10B i-BUS 解包与 GM6020 速度控制。基于既有转速 PID 工程建立独立项目，USART1 连接 VOFA、UART4 经 P1 上层 PA1 接收遥控、CAN1 控制 ID1 电机。

## 打开与构建

- EIDE：`MDK-ARM/Remote_GM6020.code-workspace`。
- Keil：`MDK-ARM/Remote_GM6020.uvprojx`。
- CubeMX：`Remote_GM6020.ioc`。
- 命令行完整构建：在本目录执行 `powershell -ExecutionPolicy Bypass -File ./Scripts/build.ps1`。
- HEX：`MDK-ARM/build/Remote_GM6020/Remote_GM6020.hex`。

构建脚本使用本机已有 EIDE unify_builder 和 ARM Compiler 5，不连接串口或 ST-Link，不执行烧录。工具路径不同的机器可通过脚本参数指定。

VS Code 中打开 `MDK-ARM/Remote_GM6020.code-workspace`，左侧 EIDE 工程选择 `Remote_GM6020`。本工程已配置 STLink、SWD、1000 kHz、烧录后运行，并明确指定下载 `build/Remote_GM6020/Remote_GM6020.hex`。按 `Ctrl+Alt+D` 或通过命令面板执行 `eide: 烧录`；若出现工程选择列表，只选 `Remote_GM6020`。之后修改源码时先执行 `eide: 构建` 或 `eide: 构建，烧录`，确保 HEX 是新生成的。

本机已经安装 EIDE 3.27.2 和它使用的 STM32CubeProgrammer CLI，工作区推荐 EIDE 扩展。EIDE 烧录成功时应显示下载完成及校验成功；无须把 HEX 转成其他格式。此配置尚未连接下载器验证，硬件烧录由实际操作确认。

EIDE 使用前面第 12 项工程已有的本地芯片包相对路径；复制整个考核仓库时应保留第 12 项目录。命令行构建从 Keil 项目源文件列表取得文件，不依赖重新生成 CubeMX。

## 运行逻辑

CH1 控制目标速度，1000…2000 对应约 −100…+100 rpm，中心 1500±30 为零速。CH5 是启停，CH6 是运行许可：两者均大于 1700 才允许运行，CH5 小于等于 1300 为明确停止位。

上电不会运行。先在健康链路、CAN 有反馈、CH6 高位时收到 CH5 停止位，再让 CH1 回中、CH5 拨到运行位。停机和故障后需重新进行这个操作。CH1 回中为零速闭环，CH5 停止解除闭环。

UART4 使用 PA1 RX（AF8），115200 / 8N1 / 无校验 / 非反相、RX-only、GPIO_NOPULL，采用单字节中断及带时间戳的 RTOS 队列。接收机 i-BUS SERVO：S→P1 上层第4脚、+→第5脚5V、−→第6脚GND。上层指原理图层次，针脚需按教程辨认；下层 DBUS 信号不可混用。

PA1 配置为 UART4 输入后，不用它输出舵机 PWM；TIM2 继续承担内部 HAL 毫秒时基。CAN1 为 1 Mbps；电机控制每 2 ms 执行。默认 PID 为 P50 / I200 / D0.002，沿用此前速度工程的初值，真实负载仍需验证。

默认继续使用 GM6020 电压协议：ID1 反馈 0x205，给定 0x1FF 的第一个槽位，给定限幅 ±15000。原始给定不是 rpm 或伏特值。电机内部模式设置保持与用户此前可运行工程一致。

## VOFA 设置及通道

USART1 对应 COM，115200 / 8N1；FireWater，Δt=20 ms。每帧固定 25 个数值，形如 `remote:...`，末尾 CRLF。

| VOFA 通道 | 内容 |
| --- | --- |
| I0…I9 | CH1…CH10 原始遥控值 |
| I10 | 目标转速 rpm |
| I11 | 实际转速 rpm |
| I12 | PID 输出原始给定 |
| I13 | 100 ms 内有合法 i-BUS 帧=1，否则0；只表示串口数据新鲜度 |
| I14 | 遥控状态机使能，1=运行许可有效 |
| I15 | 最后合法帧年龄 ms；从未收到时为999999 |
| I16 | 状态 / 故障码，见下表 |
| I17 | 累计合法帧数 |
| I18 | 累计坏帧数，校验错误+范围错误 |
| I19 | UART4 累计收到的原始字节数；持续增长表示 PA1 已经收到串口活动 |
| I20 | UART4 错误回调次数 |
| I21 | 最近一次 HAL UART 错误位：1=奇偶校验，2=噪声，4=帧格式，8=溢出，可相加 |
| I22 | 软件接收队列丢字节数 |
| I23 | 接收故障代次；UART 错误、丢字节或续接收失败时递增 |
| I24 | 最近收到的原始字节（0~255，以十进制显示），包含 UART 报错字节 |

首先显示 I0/I4/I5 检查 CH1/CH5/CH6，再显示 I10/I11 对比目标与实际转速。I13=1 不能证明无线链路健康：接收机失联后可能继续发送 Failsafe 帧，此时 I16 与 I14 表明许可已撤销。

| I16 | 含义 |
| --- | --- |
| 0 | 状态机已使能，未报告故障 |
| 1 | 上电未解锁 |
| 2 | CH5 停止 / 中间无效位置 |
| 3 | 无合法帧、100 ms 超时或关键通道值不合理 |
| 4 | CH6 不在高位，运行许可失效 |
| 5 | CAN 无新鲜反馈或电机请求提交失败 |
| 6 | 电机温度达到80°C |
| 7 | USART1 / UART4 接收丢字节、错误或命令数据陈旧 |
| 8 | 控制间隔异常 |
| 9 | CAN 发送错误 |
| 10 | 电脑 STOP |
| 11 | 启动时摇杆未回中，需再次停止→运行 |

I16 会随后续状态变化更新，故障恢复后可能显示停止位；它不是永久的故障历史。

## USART1 命令

使用 ASCII，发送真实换行 CR/LF。

| 命令 | 行为 |
| --- | --- |
| `STOP` | 清除遥控使能与电机请求；恢复需要新的停止→运行操作 |
| `P50` | 在线改 Kp，范围0…200 |
| `I200` | 在线改 Ki，范围0…1000 |
| `D0.002` | 在线改 Kd，范围0…10 |

增益命令不启动电机。本工程不接收 `S`、`K`、`OK`、`T0/T1` 等旧工程命令；遥测通道固定。增益只保存在 RAM，复位恢复源码初值。
