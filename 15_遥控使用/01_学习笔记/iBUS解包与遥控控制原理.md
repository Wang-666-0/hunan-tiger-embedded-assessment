# i-BUS 解包与遥控控制原理

## 这次的数据路径

FS-i6X 发射机 → 无线链路 → FS-iA10B 接收机 → i-BUS SERVO → P1 上层第4脚 / PA1 / UART4_RX → 字节队列 → i-BUS 解包库 → 遥控状态机 → 转速 PID → CAN1 → GM6020。

P1上层原本为舵机PWM接口；本工程把PA1复用为UART4接收，仍采用非反相115200 8N1的i-BUS数据。更换接口不改变帧格式、校验和或通道阈值。P1下层DBUS信号经过反相电路，不用于本方案。

USART1 单独把遥控通道、目标转速和电机反馈发给 VOFA。接收机串口字节与电脑命令不会进入同一个缓冲区。

## 32 字节舵机帧

本库处理常用的 i-BUS 舵机通道帧，不实现 i-BUS 传感器查询和扩展舵机配置。

| 字节位置 | 含义 |
| --- | --- |
| 0 | 0x20，整帧 32 字节 |
| 1 | 0x40，通道数据命令 |
| 2…29 | 14 个通道，每个通道 2 字节，小端 |
| 30…31 | 小端校验和 |

通道值的单位对应常规舵机脉宽数值，通常中位约 1500、端点约 1000 和 2000。帧里预留 14 个通道槽位不等于这台 10 通道设备真的有 14 个可操控通道。库默认检查前 10 个通道在 800…2200 以内；未使用槽位不按正常摇杆范围强行拒绝。

```c
channel[n] = frame[2 + 2*n] | (frame[3 + 2*n] << 8);
checksum = 0xFFFF - sum(frame[0] ... frame[29]);
received_checksum = frame[30] | (frame[31] << 8);
```

只有长度、头部、校验和和通道范围都通过，才发布新通道并更新时间。收到任何字节、发现 0x20 或读到一个残帧，都不能续期遥控在线状态。

## 自己封装的库

`App/ibus.c` 与 `ibus.h` 不依赖 STM32 HAL 和 FreeRTOS，可复用在其他 MCU 或主机测试里。

- `ibus_init` 初始化解析器。
- `ibus_feed_byte` 输入一个字节及其接收时刻，只在合法完整帧到达时返回成功。
- `ibus_feed` 接收一块字节，支持分段或连续多帧。
- `ibus_poll_timeout` 丢弃长时间未补全的残帧。
- `ibus_set_channel_validation` 设置检查通道数与数值范围。

解析器用滑动窗口重新寻找 0x20/0x40 头部。错误校验、丢字节或噪声不会使后续所有帧永久错位。统计项记录合法帧、校验错误、范围错误、丢弃字节和残帧超时。

残帧间隔超时用于重新同步，不是遥控失联阈值。遥控失联由最后一帧合法数据的时间决定，两者分别处理。

## 摇杆怎样变成目标转速

CH1 相对中位 1500 的偏差为 `channel - 1500`，约 ±500。中位附近设置死区，消除中位抖动；死区外归一化到 ±1，再映射到 ±100 rpm。

把遥控通道直接当成 CAN 输出会让电机响应随负载变化。本工程复用已有速度 PID，由目标 rpm 与 CAN 反馈 rpm 的误差计算输出。CAN 使用 GM6020 电压模式原始给定，并保留既有模式约定。

GM6020 ID1 的反馈标准帧是 0x205，电压给定使用 0x1FF 的第 1 个 16 位槽位；其他槽位保持零。电机协议采用大端，i-BUS 通道采用小端，这两种数据分别封装。

## 启停与失联

CH5 控制启停，CH6 控制运行许可。必须先读到停止位，再在摇杆中位时将 CH5 拨到运行位。以下情况会清除使能并请求零输出：

- CH5 停止或 CH6 不处于高位。
- 超过 100 ms 没有合法遥控帧。
- CAN 反馈超时、过温、发送故障或控制周期异常。
- 接收串口错误或电脑发送 STOP。

停止和故障后，高位开关不会自行恢复使能；需要新的停止→运行操作。接收机持续输出“上次通道值”时，常规 i-BUS 帧不能直接证明无线链路是否健康，所以接收机 Failsafe 的低位输出与实际关机试验也是功能的一部分。

## 软件验证能证明什么

主机测试编译实际的 C 库和状态机，用构造的串口数据与电机状态验证解包、重新同步、超时、开关使能和故障停机。它能检查代码行为；接收机真实引脚、电平、遥控菜单保存、无线失联行为、RTOS 时序和电机机械响应仍需实物验证。

通道格式参考开源项目的原始实现，接收机接口和遥控菜单参考厂家说明；来源见 `03_参考资料/资料来源.md`。
