# VOFA+ 1.3.10 转速 PID 调参面板

本工程默认输出 T1 十通道，目标与参数可以在串口在线修改。发送一次 S 命令后持续控制，直到 STOP、反馈掉线或其他停止条件触发。

当前固件默认 P50/I200/D0.002，电压给定及积分限幅均为 ±15000。反转或非零目标切到 S0 会只清积分；同向变速、重复目标和在线改参数保留历史。当前实机测试见[100 rpm 与反转阶跃验证](../01_学习笔记/100rpm与反转响应改进.md)。

## 1. 先接通串口并确认命令

数据引擎选 FireWater，串口选云台板 USART1 对应的端口，设置 115200、8 位数据、无校验、1 位停止位、无流控。

在底部发送框使用 Str/文本模式，末尾追加选 `\n`。框内只输入命令正文，例如 `P5`、`I0`、`D0`、`S30`，按发送即可。此处下拉选项会追加真正的 LF 字节，不能把两个普通字符“反斜杠、n”原样发给单片机。

| 命令 | 含义 | 接受范围 |
| --- | --- | --- |
| `S30` | 目标转速改成 30 rpm，并启用闭环 | -100～100 rpm |
| `S-30` | 反向 30 rpm | -100～100 rpm |
| `S0` | 目标为零，保持零转速闭环 | 有效目标 |
| `P5` | 设置 Kp | 0～200 |
| `I0.5` | 设置 Ki | 0～1000 |
| `D0.001` | 设置 Kd | 0～10 |
| `STOP` | 关闭闭环，撤销控制请求 | 固定命令 |
| `T1` | 输出参数、状态等十通道 | 默认模式 |
| `T0` | 只输出目标、实际两个通道 | 简洁模式 |

P/I/D 只改参数，不会自行启动电机。参数越界或语法错误会拒绝该命令，保留原值。软件重新启动后恢复 app_config.h 中的默认值；在线改参数并不写入 Flash。

## 2. 添加四条可绑定的 Str 命令

切到左侧“命令”面板，分别新建四条命令，模式选 Str。每条命令均包含末尾换行：

| 命令名称 | 命令正文模板 | 占位符意义 |
| --- | --- | --- |
| 目标转速 | `S%f[\n]` | 用滑块当前数值替换 %f |
| 比例 Kp | `P%f[\n]` | 用滑块当前数值替换 %f |
| 积分 Ki | `I%f[\n]` | 用滑块当前数值替换 %f |
| 微分 Kd | `D%f[\n]` | 用滑块当前数值替换 %f |

**命令自身要有末尾换行。** 上表 `[\n]` 是 VOFA 的换行标记，软件发送时替换为 LF；这点由官方更新日志的输入区换行和命令替换说明确认。它既不是普通 `\n` 两字符，也不是要求单片机解析方括号。底部发送框的追加换行设置，不应当被当成左侧所有控件命令也会追加换行。

本目录的 `S滑块命令.txt`、`P滑块命令.txt`、`I滑块命令.txt`、`D滑块命令.txt` 已分别包含真实 LF。用 VS Code 打开对应文件，Ctrl+A、Ctrl+C，再粘贴到 VOFA 的 Str 命令编辑框，保留末尾换行。

也可以在 VS Code 的 PowerShell 终端，从考核根目录运行下面的复制工具；它只改电脑剪贴板，不连接串口、不发送电机命令：

```powershell
& './13_PID学习与实践/03_VOFA调参/复制滑块命令.ps1' P
```

把最后的 P 换成 S、I、D 可复制其他模板；STOP 可复制停机命令。运行后直接粘贴进对应的 VOFA Str 命令框。该工具使用 `[char]10` 加入真实 LF 字节，不依赖编辑框是否解释反斜杠转义。

最后核对 VOFA 的 TX 显示或十六进制发送记录：发送帧应以 `0A` 结束；若软件编辑时删掉了换行，使用它的换行插入功能补回。实际发送内容应为文本，不是四字节浮点二进制。

目标 30 的正确最终字节是 `53 33 30 0A`（若 %f 展开成 30.000000，数字部分会更长，但末尾仍是 0A）。单片机接受整数与普通十进制小数，二者效果相同。

官方文档把 Str 占位符定义为 printf 可识别的格式，明确举例 %f、%d。按这一规则可以使用 %.2f、%.4f；本说明优先用其明确举例的 %f，避免不同版本格式选项差异。不要使用 %d 控制小增益，也不要使用指数格式 %e：本工程的命令解析器只接受普通十进制小数。

不打开循环发送；滑块事件触发时发送一条命令即可。

## 3. 把命令绑定到滑块

从控件栏拖入四个 slider。右键每个滑块，在“绑定命令”子菜单中分别选择上一步创建的目标转速、Kp、Ki、Kd。

滑块的参数由当前数值自动生成；“事件与参数”中的数值不能像按钮一样自由指定。建议关闭“滑块移动时发送”，启用“鼠标弹起时发送”和“操作输入框时发送”。这样拖动结束再发送一次，减少串口命令数量；精调时可直接在滑块右下方数值框输入数值并回车。

在右键的“设置”中修改最小值、最大值、步进；在“显示数值”中修改小数位数。当前调参面板建议使用以下范围，让已使用的 Ki=200 可以正常输入：

| 控件 | 最小值 | 最大值 | 初值 | 步进 | 显示小数位 | 可绑定的 T1 数据通道 |
| --- | --- | --- | --- | --- | --- | --- |
| 目标转速 | -100 | 100 | 0 | 1 | 2 | I0：目标 rpm |
| Kp | 0 | 200 | 50 | 1 | 2 | I3：Kp |
| Ki | 0 | 1000 | 200 | 5 | 2 | I4：Ki |
| Kd | 0 | 0.05 | 0.002 | 0.001 | 4 | I5：Kd |

这些是面板操作范围；Kp/Ki 的最大值与固件输入范围一致，Kd 的固件上限仍为 10，但面板先保留小范围。初值沿用当前实机参数，响应仍需验证。

**小数位会影响发送值。** 本机安装的 slider.qml 会先按“显示数值”的小数位对当前值取 toFixed，再将该值作为 Float 参数发送。因此 Kd 若只显示两位小数，0.001 可能被取成 0.00，实际发出去就变成零；Kd 设置四位，步进设为 0.001。

保持 T1 时，可以把每个 slider 同时绑定到表中的反馈通道。这样用发送框改参数后，滑块也会跟随单片机回传的已接受值。T0 只剩 I0/I1，参数滑块的数据绑定会缺少 I3/I4/I5，因此使用完整调参面板时保持 T1。

## 4. 波形与状态

拖入波形图，只勾选/绑定 I0、I1，分别改名为“目标转速 rpm”“实际转速 rpm”。其他通道保留在右侧数值栏观察，避免把输出原始值与转速画在同一刻度。

采样间隔 Δt 设置 10 ms，与固件名义 100 Hz 遥测一致。固件闭环每 2 ms 计算一次，100 Hz 曲线记录的是抽样后的状态。

T1 通道顺序：

| 通道 | 含义 |
| --- | --- |
| I0 | 目标转速 rpm |
| I1 | 实际转速 rpm |
| I2 | 发给电机的原始控制量 |
| I3、I4、I5 | Kp、Ki、Kd，四位小数 |
| I6 | 闭环使能：1 运行，0 停止 |
| I7 | 电机在线：1 在线，0 离线 |
| I8 | 停止原因枚举 |
| I9 | 最近命令结果：1 接受，2 语法错误，4 超范围，5 条件未就绪 |

每次改值后确认 I9=1，再观察 I0 或 I3/I4/I5 是否变为输入值。串口回显只能证明电脑发出了字符；回传值和命令结果才说明单片机接受了修改。

## 5. 第一次使用与调参顺序

1. 在 EIDE 中选中 **GM6020_SpeedPID** 再 Build、Flash；不是旧 CAN_FreeRTOS。烧录后清空 VOFA 旧数据，确认有十个通道。
2. 停止旧 K 循环发送，底部逐条发送 STOP、T1、P5、I0、D0。确认 I7=1，I3/I4/I5 为 5、0、0。
3. 发送 S20，或者将目标滑块设为 20 后松开鼠标。I6 应为 1，I0 为 20。无需再定时发送任何消息，控制器继续运行。
4. Ki、Kd 为零时先调整 Kp。响应慢可以逐步增加；持续振荡或超调明显时减小。每次只改一个参数。
5. 稳定但有持续偏差时，从很小的 Ki 开始，例如 0.5、1、2；观察稳定和超调。需要时再试很小的 Kd，例如 0.001。数值是试验起点，不是本电机已经验证的最佳参数。
6. 做同条件阶跃：目标改为 0，稳定后改为 30，观察目标和实际曲线。STOP 会退出控制；S0 仍在零速闭环，两者意义不同。
7. 结束发送 STOP。关闭 VOFA 或拔掉电脑串口不会自动停止已经锁存的转速目标。复位后恢复默认参数且不会自动启动。

调整增益保留积分输出贡献和测量历史；重复相同参数不会重置。Ki 设为 0 会清除积分贡献。修改参数可能改变输出，不意味着完全没有瞬态变化。

## 6. 消息类型、返回结果与排查

电脑发送的是 **ASCII 文本命令**；板端每 10 ms 回传的是 **FireWater 数值帧**；板端与电机之间的 **CAN 二进制帧**由程序完成，不需要在 VOFA 中手工发送 CAN 八字节报文。

- 指令大写、没有空格，一条指令一行；数字可以为整数、普通小数及带正负号的数，例如 S-20、P10.5、D0.001。P/I/D 不接受负数。
- 不接受 JSON、指数写法（D1e-3）、NaN、逗号串联（P5,I1,D0）或原样发送占位符 P%f。占位符是给 VOFA 替换的，单片机最终收到的是 P 加十进制数字。
- 多条命令可以分行，例如 P5、I0、D0，每行各有一个换行；也可以逐条发送。
- 旧工程的 B100、T100、V200、C200 不属于本工程命令。T 只接受 T0/T1。K 兼容保留，仅检查是否运行，不再需要循环发送。
- 参数只保存在 RAM，掉电/复位后恢复 app_config.h 默认值；确定最终参数后将默认值改到代码里再编译。

I9 为最近命令处理结果；它不是文字 ACK，不要等待板端打印“OK”。

| I9 | 含义与处理 |
| --- | --- |
| 0 | 尚无命令 |
| 1 | 命令被接受；同时检查目标或参数通道已变为期望值 |
| 2 | 语法错误：检查大小写、空格、占位符展开和换行 |
| 4 | 越界：S 为 ±100，P 0～200，I 0～1000，D 0～10 |
| 5 | 未就绪：启动时检查 I7 在线及温度；停止时发送 K 也会得到此结果 |
| 6 | 命令字节在队列中积压或片段间隔超过 1 秒，重新发送完整一行 |
| 7 | 串口丢字节或接收错误，已撤销控制；恢复完整命令边界后再发 S |

I8 是停止原因，与 I9 的命令结果不是同一件事：0 正常闭环，1 上电停止，2 STOP，3 反馈过期，5 过温，6 CAN 发送异常，7 串口接收故障，8 控制周期异常；4 为旧版本保留。

若仍无法发送：先停止所有循环命令，用底部手动发 P6 并追加 LF；若 I3 改成 6 且 I9=1，串口发送与接收均已通，再检查滑块命令绑定和换行。若手动也无变化，检查是否烧录本工程、USB 串口 TX 是否接板端 PA10 RX、公共地及 USART1 配置。能够看到速度曲线只证明板端向电脑的发送方向通了。

若 P6 能生效但 S20 不能启动，读取 I7/I8/I9，按反馈或故障原因检查。不要把接收消息失败与 PID 响应慢混在一起调增益。

如果增大 Ki 仍有持续偏差，先看 I2 的输出及限幅：当前默认电压模式的积分和最终输出均限在 ±15000（旧版为 ±2000），电流模式仍为 ±1000。Ki 控制积分累积速度，不能增加上限。若输出长期贴住 ±15000，说明达到了当前给定能力边界，需要检查负载、供电及协议设置；继续增加 Ki 不能让程序发出更大的给定。需要排除 D 的影响时，单独用 D0 做 PI 对比。
