## 1. 通信基础

- 串行：各位按顺序传输；并行：多根数据线同时传输多位.本任务的五种通信均属于串行通信.
- 同步：使用共享时钟协调采样，如 SPI、I²C；异步：不传独立时钟，按约定速率和同步机制恢复采样时刻，如 UART.同步不等于阻塞，异步不等于非阻塞.
- 全双工：同时双向传输，如常见 UART、四线 SPI；半双工：可双向但不能同时发送，如 I²C、CAN.

## 2. 串口（UART）：约好速度，逐位发送

TX 接对方 RX，双方匹配波特率、数据位、校验和停止位，并正确连接参考地.UART 引脚通常输出逻辑电平；RS-232、RS-485 是不同的电气接口，不能直接混接.

图中以 8E1 发送 `0x55`：

```text
空闲1 → 起始0 → D0～D7：1 0 1 0 1 0 1 0 → 偶校验0 → 停止1
```

起始位通知接收方开始接收；数据通常低位先发；偶校验使数据与校验中 1 的总数为偶数，本例有四个 1，因此校验位为 0；停止位标记结束.奇偶校验不能发现所有传输错误.

普通二进制 UART 的波特率数值等于每秒传输位数.理论传输时间＝字节数 × 每帧位数 ÷ 波特率.例如 115200 bit/s，8N1 每字节 10 位，100 字节约 8.68 ms；8E1 每字节 11 位，约 9.55 ms，不计帧间空闲.

## 3. SPI：时钟驱动，同时交换数据

| 信号 | 作用 |
| --- | --- |
| SCK | 控制器提供时钟 |
| MOSI | 控制器发送，设备接收 |
| MISO | 设备发送，控制器接收 |
| CS/NSS | 选择设备，常见低有效 |

图中控制器发送 `0xA5`，同时接收设备返回的 `0x3C`，均高位先发.双方移位寄存器随时钟同时移出和采入，因此能全双工.读取时通常也需要发送占位数据，以产生时钟.

CPOL 决定时钟空闲电平，CPHA 决定在第几个边沿采样：

| 模式 | CPOL | CPHA | 采样边沿 |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 上升沿 |
| 1 | 0 | 1 | 下降沿 |
| 2 | 1 | 0 | 下降沿 |
| 3 | 1 | 1 | 上升沿 |

SPI 没有统一的命令、地址或校验字段，具体读写帧由设备定义；通信前还要匹配位序、数据宽度和 CS 时序.

## 4. I²C：用地址共享两根线

SCL 是时钟，SDA 是双向数据，通常使用开漏输出和上拉电阻；空闲时两线均高.SCL 高时 SDA 下降为 START，上升为 STOP；普通数据在 SCL 高时保持稳定.

图中向 7 位地址 `0x50` 写入 `0xA5`：

```text
START → 地址1010000 → W=0 → ACK → 数据10100101 → ACK → STOP
```

地址选择设备，W=0 表示写、R=1 表示读；每传 8 位后，第 9 个时钟用于应答，接收方拉低 SDA 为 ACK，保持高为 NACK.设备地址与寄存器地址不同.

常见寄存器访问：

```text
写：START → 地址+W → ACK → 寄存器地址 → ACK → 数据 → ACK → STOP
读：START → 地址+W → ACK → 寄存器地址 → ACK → 重复START
   → 地址+R → ACK → 数据 → NACK → STOP
```

多字节读取时，控制器对中间字节 ACK，对最后一字节 NACK.图中的单字节写示例不包含寄存器地址.

## 5. CAN：先比较优先级，再可靠传输

### 5.1 线路与仲裁

MCU 的 CAN 控制器处理报文，收发器将逻辑 TX/RX 转为 CAN_H、CAN_L 差分信号.接收方判断两线电压差，可抑制部分共模干扰.常见高速 CAN 采用线形总线，两端各接 120 Ω 终端电阻减少反射，分支尽量短.

显性 0 能覆盖隐性 1.多个节点同时发送时，逐位比较仲裁字段，失去仲裁者停止发送并等待重试.同为标准数据帧时，ID 数值越小越优先.节点匹配位速率，利用总线边沿进行同步，没有独立时钟线不代表不需要同步.

### 5.2 用一帧理解各字段

本例：标准数据帧，ID=`0x123`，数据=`0xA5`，长度 1 字节.

| 字段 | 本例 | 通俗作用 |
| --- | --- | --- |
| SOF | 0 | “新消息开始了”，帮助接收节点对齐时序 |
| ID | 0x123，11位 | “这是什么消息、谁先说”，用于分类与仲裁，不一定是设备地址 |
| RTR | 0 | “我正在发数据”；1 表示经典 CAN 远程请求帧 |
| IDE | 0 | “号码是11位的”；扩展格式用29位ID |
| r0 | 0 | 协议保留的位置，按规定填0，不放用户数据 |
| DLC | 0001 | “后面的内容有1字节”，不包含ID、CRC等字段 |
| DATA | 0xA5 | 真正传输的内容，具体含义由双方约定 |
| CRC | 15位校验序列 | 检查内容是否在传输中被破坏，不是加密 |
| CRC界定符 | 1 | 标出校验序列结束 |
| ACK槽 | 发送方发1，接收方可拉为0 | “有其他节点正确收到这帧” |
| ACK界定符 | 1 | 标出应答槽结束 |
| EOF | 7个1 | “本帧说完了” |

实际传输从 SOF 到 CRC 序列采用位填充：连续 5 个相同位后插入一个相反位，接收方会去掉.因此图中字段拼接不等于真实总线上的完整位序列.本例不计填充有52位，加至少3位帧间间隔为55位；1 Mbit/s 下至少约55 μs.

### 5.3 学习过程中的重点问答


#### RTR 有什么用？

RTR 区分“发送数据”和“请求数据”：0 是数据帧，1 是远程请求帧.

```text
请求：ID=0x123，RTR=1，DLC=1，无数据字段
含义：请发送 ID=0x123 对应的1字节数据.
回复：ID=0x123，RTR=0，DLC=1，DATA=0xA5
含义：这就是请求的数据.
```

远程帧本身不带数据，DLC 表示请求长度.是否回复取决于节点的软件或控制器机制，不会因为收到请求就必然自动回复.CAN FD 不支持远程帧.

#### IDE 为什么在 ID 后面，而不放在前面？

可以把仲裁理解为大家同时举手：先比较“号码”，再区分号码是短的还是长的.

```text
标准帧：11位ID → RTR → IDE=0 → 后续字段
扩展帧：11位基础ID → SRR → IDE=1 → 18位扩展ID → RTR → 后续字段
```

这样两种格式先用共同的前11位参与仲裁；如果前11位相同，标准帧会在 RTR/SRR 或 IDE 位置获得优先权.如果 IDE 放在最前面，格式就会抢在号码前面影响仲裁.接收方先接收共同部分，再根据 IDE 决定如何解析后续内容.

#### r0 又是什么？

r0 是经典 CAN 标准帧中的保留位，可以理解为表格里的一个“保留格”.发送时按规定为0，不表示设备地址、长度或实际内容；控制器自动处理，通常不需要程序单独填写.

#### DLC 是什么？算的是位数还是字节数？

DLC 是数据长度码，占4位，告诉接收方后面有多少字节数据.

```text
DLC=0001（1）→ 1字节，例如 A5
DLC=0010（2）→ 2字节，例如 A5 08
DLC=1000（8）→ 8字节
```

只计算 DATA，不包含 ID、CRC 等字段.经典 CAN 数据最多8字节；CAN FD 的 DLC 超过8后采用映射，例如 DLC=9 表示12字节，不是9字节.

#### 把完整的一帧串起来，该怎么理解？

以图中的 ID=0x123、DATA=0xA5 为例：

> 新消息开始了（SOF）；消息号码是0x123（ID）；这是携带数据的标准帧（RTR=0、IDE=0）；保留格按规定填0（r0）；后面有1字节（DLC=1）；内容是A5（DATA）；检查有没有传坏（CRC）；其他节点表示正确收到（ACK）；本帧结束（EOF）.

ID 是报文标识，不一定是设备地址；ACK 只表示有人正确接收，不表示电机已执行命令.各字段的具体值和作用见总图及后文 CAN 字段表，实际线上位流还包含位填充.


### 5.4 STM32F103C8T6 的收发结构

发送：软件填写 ID、长度和数据 → 发送邮箱 → 仲裁并发送.接收：硬件验帧 → 过滤器 → 接收 FIFO → 软件读取.

- 3 个发送邮箱：缓存待发报文，装入邮箱不等于发送成功.
- 2 个接收 FIFO，每个可存3帧：需及时读取，避免溢出.
- 14 个过滤器组：列表模式匹配指定 ID，掩码模式比较指定的位，并将报文分配到 FIFO.过滤器决定软件接收哪些报文，不决定仲裁优先级.

CAN 还通过错误检测、错误计数与 Bus-off 等机制管理故障.学习重点是能理解收发、过滤、反馈解析和错误处理；上述数量针对本板型号.

## 6. CAN FD：更多数据，数据阶段可提速

CAN FD 保留仲裁机制，单帧最多64字节；启用 BRS 后数据阶段可切换为更高位速率，并非整帧都高速.

| 字段 | 作用 |
| --- | --- |
| FDF=1 | 告诉接收方按 FD 格式解析 |
| BRS=1 | 启用数据阶段位速率切换 |
| ESI | 0为 Error Active，1为 Error Passive，表示发送节点错误状态 |
| RRS=0 | 替代经典 CAN 的 RTR；FD 不支持远程帧 |
| DLC | 0～8对应同样字节数；9～15对应12、16、20、24、32、48、64字节 |
| CRC | 载荷不超过16字节用17位，超过16字节用21位校验 |

图中 DLC=9 表示12字节，不是9字节.STM32F103C8T6 内置 CAN 不支持 FD，实践需要支持 FD 的硬件；普通经典 CAN 节点也不能直接假定可与 FD 帧共存.结合 RM 方向，先用熟经典 CAN，再深入 CAN FD.

## 7. 速度、距离与选型

| 协议 | 常见速度与连接范围 | 优势与局限 | 应用 |
| --- | --- | --- | --- |
| UART | 9600、115200 bit/s等；直接逻辑电平适合短距离 | 简单，调试方便；需匹配参数并自行组应用报文 | 调试、模块通信 |
| SPI | MHz级时钟，通常板内 | 快、可全双工；引脚多，无统一ACK/CRC | IMU、屏幕、Flash |
| I²C | 常见100/400 kbit/s，通常板内 | 两根线连多个设备；受地址冲突、上拉和电容影响 | 传感器、EEPROM |
| CAN | 最高1 Mbit/s，适合设备间总线 | 差分、多节点、错误管理完善；需收发器和规范布线 | 电机、车辆、机器人 |
| CAN FD | 数据阶段可更快，实际取决于硬件和总线 | 载荷更大；需要FD控制器与合适收发器 | 较大数据量的节点通信 |

距离没有脱离速率、线缆和布线条件的固定值；最高位速率也不等于有效数据吞吐量.
