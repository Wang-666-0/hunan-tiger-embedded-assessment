# 从烧录到 VOFA+ 姿态显示

这份笔记只讲如何使用本工程。BMI088 驱动、六轴融合、零偏校准和串口协议已经按模块放在工程的 `App` 目录中，不需要另外安装“驱动软件”。

## 1. 先认识数据流程

```text
上电 → 初始化 BMI088 → 连续静止校准 → 用重力初始化姿态
                                          ↓
每 5 ms：读六轴 → 减陀螺仪零偏 → Mahony → 欧拉角 → USART1 → VOFA+
```

BMI088 不是直接输出欧拉角的传感器。它输出加速度和角速度，程序再计算姿态。具体阅读位置：

| 你要了解的内容 | 对应模块 |
| --- | --- |
| SPI 片选与本板引脚 | bmi088_port.c/.h |
| 传感器初始化、量程、读数与单位 | bmi088.c/.h |
| 启动时为什么要放稳 | imu_calibration.c/.h |
| 怎样调用六轴融合与转换欧拉角 | mahony.c/.h |
| 5 ms 周期在哪里设置、故障怎样恢复 | imu_app.c/.h |
| 发帧顺序和帧尾 | vofa_telemetry.c/.h |

本版本的 Mahony 每次更新显式接收实际经过的时间，单位为秒，不依靠某份参考源码里的固定 `sampleFreq` 宏。正常目标是 5 ms；任务偶发延迟时使用实际时间更新，不能把异常长的采样间隔无限制用于积分。查看 `imu_app.c` 的时间与异常分支。

## 2. 复核 CubeMX 配置

继续使用本任务 `Output/BMI088_Read/BMI088_Read.ioc`，不需要另建同名工程。以下是本板已核对的关键项：

| 配置项 | 应有设置 |
| --- | --- |
| RCC HSE | Crystal/Ceramic Resonator，外部晶振 25 MHz |
| PLL | HSE 输入，M = 25，N = 336，P = 2 |
| 系统总线 | SYSCLK/HCLK 168 MHz；APB1 /4 = 42 MHz；APB2 /2 = 84 MHz |
| SYS Debug | Serial Wire，保留 PA13/PA14 |
| SYS Timebase | TIM2 |
| SPI1 | Full-Duplex Master；Hardware NSS Disable；Software NSS |
| SPI1 参数 | Mode 0：CPOL Low、CPHA 1 Edge；8 Bits；MSB First；Prescaler 32 |
| SPI1 引脚 | PA5 SCK、PA6 MISO、PA7 MOSI |
| 两个片选 | PA4 陀螺仪、PC4 加速度计；GPIO 推挽输出；初始 High |
| 两个中断 | PB0 加速度计、PC9 陀螺仪；本版轮询，保持输入 |
| USART1 | Asynchronous，PA9 TX、PA10 RX，115200、8 位、1 停止位、无校验、无流控 |
| FreeRTOS | CMSIS_V2；1000 Hz；heap_4；总堆 10240 字节 |
| imuTask | Normal；栈 512 words = 2048 bytes |

本工程没有启用 MCU 的 USB/SDIO/RNG，PLLQ 的灰色项不用强行解锁，也不用为了修改它启用无关外设。PC9 已用于 IMU，引脚冲突使 RCC 的 MCO2/I2S_CKIN 选项不可用，不需要勾选。

如果以后重新生成 CubeMX 代码，先保存工程，勾选保留用户代码；生成后检查 `App` 源文件组和头文件路径仍在 EIDE/Keil 工程中。重新生成可能覆盖工程文件中的源文件列表。

## 3. 接线：只用已经连接的 USART1

本程序通过 USART1 发帧，不通过板上的 Type-C 虚拟串口。

| 云台板 | USB-TTL 模块 |
| --- | --- |
| USART1 TX / PA9 / 接口 T | RXD |
| USART1 RX / PA10 / 接口 R | TXD，可选；本次只显示时不用发送命令 |
| GND / 接口 G | GND |

使用 3.3 V TTL 电平，不要把 RS232 电平或 5 V TX 信号接到 MCU。板子沿用已有正确供电方式，不额外连接 USB-TTL 的 VCC，避免反向供电。上电前核对板接口的丝印，不根据插头外形猜线序。

ST-Link 连接 SWDIO（PA13）、SWCLK（PA14）和 GND，并按现有下载器要求连接目标电压参考。不要为了做 IMU 实验启动电机、CAN 或 IMU 加热功能。

## 4. 编译与烧录

1. 在 VS Code 打开本任务 `Output/BMI088_Read/MDK-ARM/BMI088_Read.code-workspace`，把 EIDE 的 **BMI088_Read** 设为当前活动项目。现在该工程已经包含姿态业务；确认打开的是第 14 项，不是备份中的旧空任务或 `UART_DMA` 等其他工程。
2. 先执行完整重新构建；若发生错误，处理第一条错误，不把旧 HEX 当成这次成功结果。
3. 确认项目的 App 分组包含六对业务文件，头文件路径包含 `../App`，FreeRTOS/HAL 源文件已加入。
4. 下载器选择现有的 ST-Link，下载本工程刚生成的 HEX。可以使用 EIDE 的烧录功能，也可以打开本任务 Keil 工程编译后下载；两者输出目录不同，不混用旧产物。
5. 复位板子，放在稳固平面上，保持静止至少 3～5 秒。最容易核对的初次姿态是传感器 +Z 朝上、板面接近水平。

EIDE 构建的当前 HEX 为 `Output/BMI088_Read/MDK-ARM/build/BMI088_Read/BMI088_Read.hex`。如要在终端复现构建，在工程目录执行 `powershell -ExecutionPolicy Bypass -File .\Scripts\build.ps1`。该脚本只编译，烧录仍由你确认连接和目标后执行。

EIDE 沿用当前工程 `MDK-ARM/.pack` 中的 STM32F4xx 芯片支持包，不再跨任务目录引用。如果只复制本工程到另一台电脑且未带上芯片包，在 EIDE 中重新选择本机的 STM32F4xx_DFP 支持包。不要把设备包缺失误判成 BMI088 算法错误。

启动有供电稳定等待、传感器初始化和约 2.5 秒连续静止校准，因此刚复位没有姿态帧是正常启动现象之一。校准期间明显摇动会重新累计；每次复位都会重新校准。运行阶段的初始化/采样故障也可能进入重试和重新校准。

必须真的把板子放在稳固位置，不能边拿着缓慢旋转边等待校准。阈值和方差检查只能排除部分运动，六轴数据无法完全区分很慢的匀速偏航与陀螺仪零偏。本工程每轴校准角速度上限为 0.04 rad/s（约 2.3 度/秒）；它是运动拒绝阈值，不是允许用户这样旋转的速度。

## 5. 配置 VOFA+ 串口接收

1. 插好 USB-TTL，在电脑设备管理器找到它的 COM 端口。
2. 打开 VOFA+，通信方式选择串口，选同一个 COM 端口。
3. 设置波特率 **115200**、数据位 **8**、停止位 **1**、校验 **None**、流控 **None**。
4. 数据协议/协议引擎选择 **JustFloat**，不是 FireWater。
5. 关闭其他占用该 COM 的串口助手，打开 VOFA 的串口连接，再复位板子并放稳等待。

解析成功后应有三个数据通道：I0、I1、I2。通道名称可以改成 Roll_deg、Pitch_deg、Yaw_deg；更名只是显示，不改变帧内顺序。控件通过右键菜单绑定数据。[VOFA 数据绑定说明](https://www.vofa.plus/docs/learning/start/data_cmd_parameter/)

## 6. 确认三个通道和帧格式

| 数据通道 | 物理量 | 单位 | Cube 对应分量 |
| --- | --- | --- | --- |
| I0 | Roll 横滚 | 度 | X |
| I1 | Pitch 俯仰 | 度 | Y |
| I2 | Yaw 相对偏航 | 度 | Z |

每一帧是三个 32 位小端 float，紧接固定帧尾 `00 00 80 7F`，合计 16 字节。不要向 USART1 混入 `printf` 日志、字符串前缀或换行。[JustFloat 协议说明](https://www.vofa.plus/docs/learning/dataengines/justfloat/)

正常每 5 ms 一帧，即 200 帧/秒、3200 字节/秒。115200、8N1 下发送一帧约 1.39 ms，约占串口有效带宽 28%，本版可用任务内轮询发送。VOFA 的界面刷新不一定等于接收帧率，不要求三维模型每帧都绘制一次。

UART 超时后，程序会在下一完整帧之前先补发帧尾以重新建立边界，防止残留半帧拼进新角度包。JustFloat 本身没有校验或固定三通道长度约束，通信故障时仍可能短暂出现残缺包；若通道数量异常，恢复接线后清空接收数据或重开连接。故障/重同步/任务超期时不承诺仍保持 200 Hz。

二进制帧在普通文本窗口表现成乱码并不表示错误。如果需要查看原始数据，选择十六进制显示，检查帧尾；以三个已解析通道能随动作连续变化作为正常通信的主要证据。

## 7. 先显示数值，再显示曲线

在 VOFA 的控件区域添加三个可显示数值的控件；具体名字可能随版本不同。分别右键绑定 I0、I1、I2，标题改为 Roll/Pitch/Yaw，显示 1～2 位小数即可。

再显示三个通道的时间曲线。初次检查先看单轴动作：

1. 静止：Roll/Pitch 应较稳定；Yaw 初始附近会有慢漂移。
2. 缓慢绕传感器 X 轴倾斜：Roll 应是主要变化量。
3. 缓慢绕传感器 Y 轴倾斜：Pitch 应是主要变化量。
4. 保持接近水平并绕 Z 轴转动：Yaw 应明显变化。

“绕传感器轴”不是随意按板外形叫左/右。初次实验记录芯片 X/Y/Z 与板子边缘的对应方向。加速度和陀螺仪使用同一右手坐标系；不要只修改其中一组数据的符号。

## 8. 用 Cube 控件显示三维姿态

1. 在 VOFA 控件区添加 **Cube**。
2. 进入控件的姿态数据绑定设置，选 **欧拉角/Euler** 模式，不选 Quaternion。
3. 单位选 **角度/Degree**，因为程序已经发送度；不要再次乘 `180/π`。
4. X 分量绑定 **I0（Roll）**，Y 绑定 **I1（Pitch）**，Z 绑定 **I2（Yaw）**。
5. 拖动鼠标只改变观察视角，滚轮改变缩放；不改变传感器计算的姿态。需要时在右键的模型视图菜单选择正视/侧视。

Cube 支持 Euler 与 Quaternion 两种模式以及模型视角、模型文件、位姿偏置等设置。[Cube 官方说明](https://www.vofa.plus/docs/learning/widgets/cube/)

先缓慢做上节四个动作，看模型是否随实际动作一致。若数值正确而模型初始朝向不同，可双击控件中央或从右键菜单打开位姿偏置设置；这只修正模型显示偏置，不校正传感器零偏。

不同模型的默认轴方向、控件旋转约定和观察视角可能不同。本代码使用右手坐标和 ZYX 欧拉角提取；VOFA 文档未明确承诺所有组合旋转的内外禀顺序都与这一约定一致，因此不要只凭接了 I0/I1/I2 就宣布模型方向完全正确。按单轴和组合轴动作验收；需要改模型坐标时，明确记录变换，不盲目交换轴或单独取反。首次考核展示优先使用默认 Cube。

## 9. 怎样解读显示的姿态

Roll/Pitch 表示相对重力方向的倾斜，不要求“以当前放置角度全部清零”。Yaw 的参考在本次启动时设为零，表示本次启动后的相对转角，没有绝对北向。

| 观察结果 | 解释 |
| --- | --- |
| 启动数秒后才出现通道 | 正常的初始化与静止校准过程之一 |
| 静止时 Yaw 慢慢变化 | 六轴无绝对航向约束；温漂/残余零偏会累计 |
| 回到水平后 Roll/Pitch 回到接近原值 | 重力方向参与了倾斜校正 |
| 快速平移或碰撞时短暂偏离 | 加速度包含运动分量，不只有重力 |
| 接近 Pitch ±90° 时 Roll/Yaw 跳变 | 欧拉角表示奇异；四元数姿态本身不一定出错 |
| 跨过 ±180° 后曲线从一端跳到另一端 | 角度范围回绕，不等于真的瞬间反转 |

请用缓慢转动展示，避免碰撞、长时间高速旋转或不停平移。没有磁力计，不能把 Yaw 缓慢漂移描述为驱动已获得“绝对精准航向”。本任务也没有温控与温度补偿闭环。

## 10. 常见问题按顺序排查

| 问题 | 先检查什么 |
| --- | --- |
| COM 打不开 | COM 选错、其他软件占用、USB-TTL 驱动/连接问题 |
| 有串口字节但无 I0/I1/I2 | 是否选 JustFloat；是否有正确帧尾；有没有混入文字日志 |
| 复位后一直无数据 | 先确保连续静止；再核对供电、实际烧录项目、PA4/PC4 双片选和 SPI 参数 |
| 芯片初始化一直失败 | 是否实际装的是 BMI088；不能把另一颗 ICM42688 当作 BMI088 使用 |
| 数字正常但 Cube 不动 | 是否 Euler、Degree；X/Y/Z 是否绑定 I0/I1/I2 |
| Cube 方向看起来反了 | 先用数值验证轴，再检查传感器轴、模型初始朝向和观察视角 |
| 每次启动倾斜不归零 | Roll/Pitch 由重力初始化，并非当前姿态作为零点；这通常正常 |
| 模型突然冻结但串口还连接 | 可能停止发帧并进入初始化/采样恢复；旧值不会自动证明传感器仍正常 |
| 链接出现 L6406E/L6407E | 检查当前 EIDE 项目的 Flash/RAM 布局；执行完整重新构建，不使用旧空任务 HEX |

不要为了检查串口直接给 JustFloat 通道追加调试字符串。保留纯姿态帧有利于控件稳定解析。
