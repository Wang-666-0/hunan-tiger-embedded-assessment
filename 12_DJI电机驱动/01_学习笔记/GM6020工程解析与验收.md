# 第十二项考核 · GM6020 电机驱动学习笔记

整理日期：2026-10-06。对应本目录 `Output/CAN_FreeRTOS` 的模块化、关键行注释版本。

## 1. 本次考核要学会什么

目标：辨认并修改电机 ID；通过 CAN 读取角度、转速、电流和温度；发送控制报文使电机转动。

本工程使用 STM32F405 云台板的 CAN1 与 GM6020 通信，USART1 接收电脑命令并输出 VOFA+ FireWater 数据。默认电机 ID 1、电压控制协议，上电没有非零请求。

**最核心的两条流程：**

```text
读取：电机反馈 → CAN1 接收中断 → 帧队列 → 解包 → 反馈快照 → 控制/遥测
控制：串口字节 → 字节队列 → 完整命令 → 输出请求 → 周期检查 → CAN 命令
```

本工程实现的是电压/电流协议的原始给定，**没有外部速度 PID 或位置 PID**。V500 不是 500 rpm，也不是 500 V；零给定不等于位置保持。

资料以用户提供的 [GM6020 使用说明 V1.4（2023.10）](https://rm-static.djicdn.com/tem/17348/RoboMaster%20GM6020%E7%9B%B4%E6%B5%81%E6%97%A0%E5%88%B7%E7%94%B5%E6%9C%BA%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E20231013.pdf) 为准，重点看印刷页 2、5、6、7；本地副本在 `03_参考资料`。串口输出格式参考 [FireWater 官方协议](https://www.vofa.plus/docs/learning/dataengines/firewater/)。

## 2. 连接与 CubeMX 配置

GM6020 使用外部电源；CANH/CANL 接云台板 CAN1；USART1 通过 USB 转串口接电脑。两个 CAN1 插口属于同一条总线，CAN2 是另一个控制器；本实验断开此前 CAN1↔CAN2 的测试桥接，应用只启动 CAN1。

MCU 的 CAN_RX/CAN_TX 是逻辑电平接口，板上收发器将 TX 转成 CANH/CANL 差分信号，并把总线状态转成 RX。这里的 RX/TX 属于 CAN 控制器，不是 UART 协议。

| 项目 | 当前配置 | 作用 |
| --- | --- | --- |
| MCU | STM32F405RGTx | 云台板主控 |
| HSE / SYSCLK | 25 MHz / 168 MHz | PLLM=25、PLLN=336、PLLP=2 |
| AHB / APB1 / APB2 分频 | 1 / 4 / 2 | PCLK1=42 MHz，PCLK2=84 MHz |
| CAN1 引脚与模式 | PA11 RX、PA12 TX，Normal | 经板上收发器通信 |
| CAN 位时序 | Prescaler=3、BS1=11、BS2=2、SJW=1 | 1 Mbps |
| 自动重发 / bus-off 管理 | Enable / Enable | CAN 硬件提供重发及恢复条件 |
| USART1 | PA9 TX、PA10 RX，115200、8N1 | 接收命令、输出遥测 |
| CAN1 RX0/TX、USART1 中断 | 优先级 5，子优先级 0 | 符合当前 RTOS 的 FromISR 调用条件 |
| HAL / RTOS 时基 | TIM2 / SysTick | HAL 毫秒计时与 RTOS 调度分开 |
| RTOS tick / 堆 | 1000 Hz / 16384 字节 | 一个 tick 为 1 ms |

CAN 波特率必须使用 **PCLK1=42 MHz**，不能使用 APB1 定时器的 84 MHz：

```text
波特率 = PCLK1 / [Prescaler × (1 + BS1 + BS2)]
       = 42 MHz / [3 × (1 + 11 + 2)] = 1 Mbps
采样点 = (1 + 11) / 14 ≈ 85.7%
```

当前 PLLQ=4，未用的“48 MHz”分支实际为 84 MHz，不影响本实验的 CAN；以后启用需要 48 MHz 的 USB/SDIO/RNG 时，应改 Q=7 并重新核对时钟。

## 3. 电机 ID 与 CAN ID

拨码 1、2、3 是 Bit0、Bit1、Bit2，ON=1，电机 ID=开关1×1+开关2×2+开关3×4。第四位是终端电阻开关，不参与 ID。

按编号 1→4 记录的 `1001` 表示 **ID 1，终端电阻接入**，不能直接当成四位二进制数 9。正常状态的绿灯每秒闪 N 次，也可用于辨认 ID N。

| 电机 ID | 反馈 ID | 电压命令 ID | 电流命令 ID | 控制值位置 |
| --- | --- | --- | --- | --- |
| 1 | 0x205 | 0x1FF | 0x1FE | data[0]、data[1] |
| 2 | 0x206 | 0x1FF | 0x1FE | data[2]、data[3] |
| 3 | 0x207 | 0x1FF | 0x1FE | data[4]、data[5] |
| 4 | 0x208 | 0x1FF | 0x1FE | data[6]、data[7] |
| 5 | 0x209 | 0x2FF | 0x2FE | data[0]、data[1] |
| 6 | 0x20A | 0x2FF | 0x2FE | data[2]、data[3] |
| 7 | 0x20B | 0x2FF | 0x2FE | data[4]、data[5] |

**电机 ID 是设备编号，CAN ID 是报文标识符。** 反馈 ID=0x204+电机 ID；控制报文按组共享 ID，用两字节槽位区分电机。

修改 ID 的示例：STOP 后断电，将前三位改为按编号排列的 `010`，即 ID 2；终端电阻按总线端点配置。将 `app_config.h` 的 `GM6020_MOTOR_ID` 改为 2，重新编译烧录、上电，核对反馈变成 0x206、控制值进入 data[2] 和 data[3]。软件宏不能改变物理拨码。

## 4. 工程应该按什么顺序读

先读 `app_config.h` 看参数，再读 `can_tasks.c` 看任务关系；重点读 `gm6020_codec.c`、`can_protocol.c`、`gm6020.c` 理解反馈，然后看 `motor_control.c`、`motor_console.c` 和 `can_transport.c`。

| App 文件 | 实现的功能 | 为什么分开 |
| --- | --- | --- |
| app_config.h | ID、模式、限幅、超时、周期、栈和优先级 | 调整参数不必在多个 .c 中找数字 |
| can_tasks.c | 创建接收、控制和串口任务 | 只组织何时执行，不混入字节解包 |
| gm6020_codec.c | 解码反馈、判断在线、编码命令 | 协议规则集中，能独立测试 |
| can_protocol.c | 大端 16 位读写、补码转换 | 多种字段复用同一字节工具 |
| gm6020.c | 发布反馈和复制一致快照 | 统一管理跨任务共享数据 |
| motor_control.c | 保存请求、周期检查、发送和撤销 | 串口请求与 CAN 发送职责分开 |
| motor_console.c | 字节组行、命令解析、FireWater 输出 | 输入协议和遥测格式集中 |
| can_transport.c | CAN 启动、FIFO 搬运、队列、邮箱、HAL 回调 | 硬件操作不依赖具体电机字段 |
| can_debug.c | 基础统计、故障码、可选额外诊断 | 诊断不再承担正常电机解析 |

启动流程：main 初始化 HAL、时钟和外设；freertos.c 创建 CAN 帧队列、UART 字节队列和任务；调度器启动后，接收任务开启 CAN，串口任务开启接收。先建队列再开中断，防止中断访问尚不存在的缓冲。

| 任务 | 优先级 | 栈容量 | 工作方式 |
| --- | --- | --- | --- |
| CAN_RX | 4 | 256 words=1024 字节 | 阻塞等待帧，直接调用电机解析 |
| MOTOR_CTRL | 3 | 384 words=1536 字节 | 名义每 2 ms 检查并更新给定 |
| MOTOR_UART | 2 | 512 words=2048 字节 | 每 5 ms 处理输入，每 20 ms 输出遥测 |

任务优先级数字越大越高，中断优先级数字越小越紧急。周期任务用 `vTaskDelayUntil` 从固定基准安排唤醒，减少把执行耗时累加进周期；名义周期不是实测精密时间戳。

额外原始帧副本、硬件采样和栈余量默认不编译、不执行，`APP_ENABLE_DIAGNOSTICS=0`。正常电机解析、控制、串口遥测和基本收发统计不依赖这个开关。

## 5. 重点：反馈如何解包

```text
CAN1 FIFO0 → HAL_CAN_RxFifo0MsgPendingCallback
→ xQueueSendFromISR → CanRxTask → GM6020_ParseFeedback
→ GM6020_DecodeFeedback → gm6020_feedback
```

中断只搬运帧，不解包、不打印、不等待发送。队列复制整个 CanRxMessage，所以中断的局部变量退出后，消息仍有效。

接收消息中的 source 是控制器编号，id 是报文 ID，dlc 是长度，data 是八字节副本，received_ms 是中断搬运时刻。过滤器先接受所有 ID，中断保留标准数据帧；解码再检查 CAN1、目标反馈 ID、DLC=8，以及编码值在 0～8191。

| 字节 | 字段 | 类型与含义 |
| --- | --- | --- |
| data[0]、data[1] | encoder | 无符号大端 16 位，单圈 0～8191 |
| data[2]、data[3] | speed_rpm | 有符号大端 16 位，转速 rpm |
| data[4]、data[5] | current_raw | 有符号大端 16 位，转矩电流原始值 |
| data[6] | temperature | 温度，℃ |
| data[7] | 保留 | 不作为帧序号或校验和 |

**大端拼接：高字节在前。**

```c
uint16_t raw = ((uint16_t)data[0] << 8) | data[1];
```

左移八位把高字节放到高八位，按位或合并低字节。传入 `&message->data[2]` 时，辅助函数的 data[0]/data[1] 就是原报文的 data[2]/data[3]，读出的正好是转速。

**有符号补码：**先拼为无符号数；大于 32767 时用 32 位中间量减去 65536。例如 FF 9C=65436，65436−65536=−100。

**单圈角度：** `angle_deg=encoder×360/8192`。4096 对应 180°，8191 接近 360°。没有零点校准或累计圈数，越过 8191→0 会回到 0°；这是电机机械角度，不是 MPU 欧拉角。

完整例子：反馈 ID=0x205，DLC=8，DATA=`10 00 FF 9C 01 F4 23 00`。

| 解析结果 | 值 |
| --- | --- |
| 编码值 / 角度 | 0x1000=4096 / 180° |
| 转速 | 0xFF9C → −100 rpm |
| 电流原始值 | 0x01F4=500 |
| 温度 | 0x23=35℃ |
| 最后一字节 | 保留，不参与以上换算 |

手册没有给出反馈 current_raw 的安培换算比例，保留原始值，不能套用控制命令的电流比例。

| 函数 | 参数与结果 | 设计意义 |
| --- | --- | --- |
| CanProtocol_ReadU16BE(data) | data 指向至少两个字节；返回 uint16_t | 拼接高低字节 |
| CanProtocol_ReadI16BE(data) | 返回 int16_t | 显式恢复补码负数 |
| CanProtocol_WriteI16BE(data,value) | 输出两个字节，value 为有符号给定 | 打包正负控制值 |
| GM6020_DecodeFeedback(message,result) | 输入报文、输出反馈；返回 1/0 | 先全部校验再写输出，错误帧不覆盖有效结果 |
| GM6020_ParseFeedback(message) | 返回 1/0 | 调用解码，累计帧数，发布共享反馈 |
| GM6020_GetFeedback(snapshot) | 调用方提供输出结构体 | 短临界区复制完整快照 |
| GM6020_IsOnline(snapshot,now_ms) | 反馈年龄小于 200 ms 且收到过有效帧时返回 1 | 判断反馈新鲜度 |

解码在临界区外完成，临界区只发布或复制结构体，避免其他任务读到两帧混合字段。volatile 保留共享访问，但不保证多字段同时更新。

在线时间来自中断接收时刻，不是队列处理时刻；排队不能使旧反馈变新。无符号时间差处理计数回绕；先取快照再读当前时间，避免抢占导致当前时间早于反馈时间。

## 6. 重点：怎样构造并发送控制报文

```text
V500 加换行 → 字节队列 → 整行命令 → MotorConsole_ProcessLine
→ MotorControl_SetOutput → 保存请求
→ MotorControl_Step → GM6020_BuildCommand → CanTransport_Send
```

`GM6020_BuildCommand(motor_id,mode,raw,can_id,data)`：motor_id=1～7；mode=电压/电流协议；raw=有符号原始给定；can_id 和 data[8] 为输出。返回 1 组帧成功，0 参数无效。

它先清零八个字节，再根据电机 ID 找到组 ID 和槽位，将给定写入槽位×2的位置。未使用槽位是零，本工程只控制一台电机；同组其他电机也会收到零给定。多电机时应统一维护所有槽位后再组帧。

| 模式 | 手册协议范围 | 工程教学范围 | 注意 |
| --- | --- | --- | --- |
| 电压，默认 | ±25000 | ±2000 | 原始给定，不直接当作伏特或 rpm |
| 电流 | ±16384 | ±1000 | 命令全量程对应 ±3 A，只指命令换算 |

电流模式要求电机固件至少 1.0.11.2、Assistant 至少 2.7，并开启电流环。MCU 模式宏只选择发送协议，不会修改电机内部开关；默认电压版本要与电机电压模式匹配。

```text
ID1，电压 +500：ID=0x1FF，DATA=01 F4 00 00 00 00 00 00
ID1，电压 -500：ID=0x1FF，DATA=FE 0C 00 00 00 00 00 00
ID2，电压 +500：ID=0x1FF，DATA=00 00 01 F4 00 00 00 00
```

| 控制函数 | 参数与结果 | 做什么 |
| --- | --- | --- |
| MotorControl_Limit() | 内部返回教学上限 | 区分电压/电流限幅 |
| MotorControl_SetOutput(raw) | 1 接受、0 拒绝 | 非零检查限幅、在线、CAN 就绪和温度，成功后保存请求 |
| MotorControl_Stop(reason) | reason 为停止原因枚举 | 禁用并清零请求，不在此操作 CAN |
| MotorControl_KeepAlive() | 返回是否续期成功 | 只续期已启用且未超时的请求 |
| MotorControl_GetState(snapshot) | 输出一致控制状态 | 串口遥测读取状态 |
| MotorControl_Step() | 每 2 ms 调用 | 检查条件，选出给定，编码并提交邮箱 |

requested_raw 是用户请求，output_raw 是本轮准备发送的值，last_sent_raw 是最近成功提交邮箱的值。三者都不是电机实测转速，提交也不保证目标电机已执行。

| stop_reason | 含义 |
| --- | --- |
| 0 | 请求正常启用 |
| 1 | 上电初始停止 |
| 2 | STOP 或零给定 |
| 3 | 反馈超时 |
| 4 | 三秒没有更新给定或 K 续期 |
| 5 | 温度达到 80℃ |
| 6 | CAN 发送失败或上轮邮箱仍挂起 |
| 7 | 串口接收可靠性失效 |

80℃ 是本工程阈值，不是手册内置保护温度。停止后即使反馈恢复、温度下降或收到 K，也不会自动重新启用。

正常情况下报文应在下个 2 ms 周期前发完。旧邮箱仍挂起时撤销输出并取消旧帧，避免无 ACK 时持续重发旧非零命令；反馈离线时不提交新控制帧。线路断开无法保证零帧送达，零给定也不是机械抱闸。

## 7. 串口命令、组行和遥测

电脑发送的是自定义命令，MCU 输出的是 FireWater，两者方向和格式不同。VOFA 发送栏选择 ASCII/文本，附加真实 CR、LF 或 CRLF；不要输入字面字符反斜杠加 n。

| 命令 | 作用 |
| --- | --- |
| V500 / V1000 | 正电压原始给定，有效期三秒 |
| V-500 | 负电压原始给定，实际方向按安装观察 |
| V0 / STOP | 撤销给定、禁用请求 |
| K | 给已启用且未超时的请求再续期三秒 |
| C500 / C-500 / C0 | 电流协议版本使用，默认电压版本拒绝 |

持续试转可每秒发 K；停止后 K 不能重启。语法、模式或超限错误不覆盖原请求，原请求仍受三秒期限约束。旧任务的 B100 在本工程未定义。

串口流程拆为三步，便于逐个阅读：

1. `MotorConsole_RearmReceive` 只负责在接收错误后重启 HAL 单字节 RX。
2. `MotorConsole_HandleByte(received)` 验证时间和故障代次、拼接一行，完整行才交给解析。
3. `MotorConsole_ProcessLine(line)` 判断 STOP/K/V/C，调用控制接口并记录结果。

`MotorConsole_Poll` 只组织以上步骤，每轮最多取 128 个字节，空队列不阻塞。ParseNumber 逐位检查十进制符号、字符和 int16 范围，不接受尾部杂字符。

丢字节不能把 V1000 的残片变成 V100。每个队列项保存故障代次，故障前后片段不能混用；错误行丢弃至下个换行。恢复后先发空换行，再发完整命令。32 字节缓冲留一位结束符；排队或片段间隔达到一秒按陈旧输入处理。

FireWater 每行固定九通道，名称后冒号，数值间逗号，末尾真实 CRLF：

```text
motor:180.00,-100,500,35,1,500,1,0,1
```

| 通道 | 数据 |
| --- | --- |
| 0 | 单圈机械角度，度 |
| 1 | 实测转速，rpm |
| 2 | 反馈电流原始值 |
| 3 | 温度，℃ |
| 4 | 在线状态 0/1 |
| 5 | 本轮输出给定 |
| 6 | 请求启用 0/1 |
| 7 | 停止原因 |
| 8 | 最近命令结果 |

命令结果：0 未处理，1 接受，2 语法错误，3 模式错误，4 超限，5 启用或续期条件不满足，6 陈旧输入，7 接收故障。

`snprintf` 先组完整文本，检查所需长度大于零且小于缓冲容量，再同步 `HAL_UART_Transmit`。角度用百分之一度整数格式化，避免串口 `%f` 开销。只有一个串口发送任务，局部缓冲在同步发送返回前有效。

VOFA 选择 FireWater、115200、8N1，波形 Δt 可按名义周期设 20 ms；不同量纲可分图显示。跨模块快照可能相差一个任务周期，实际发送间隔需上板观察。

| 三个 TASK_PRIORITY | 4 / 3 / 2 | 接收高于控制，控制高于串口 |
| APP_ENABLE_DIAGNOSTICS | 0 | 默认关闭额外诊断，正常功能独立运行 |

参数改变后重新编译烧录。控制周期缩短会增加 CPU 和总线负载，遥测周期缩短会增加串口负载，不是越短越好。任务栈单位为 word，F405 上等于四字节；栈和 RTOS 堆是不同配置。

## 9. 使用与功能验收

1. 在 EIDE 选择 GM6020_FreeRTOS，编译并烧录当前工程。配置目标仍叫 CAN_FreeRTOS，这是配置名称，不是第十一项工程。
2. 连接 VOFA，先不发非零命令。确认通道4为1，手动转轴后通道0随角度变化，温度合理。
3. 默认电压模式发 V500 加换行，确认通道8=1、通道6=1、通道5=500；结合实际转动和通道1的速度确认执行。
4. 不续期三秒后应禁用并清零给定，通道7=4；STOP 应得到停止原因2。反向测试前先停止，再发送 V-500。
5. 按第3节改变电机 ID，同时修改软件宏，核对新的反馈和控制槽位，完成 ID 修改要求。

低给定可能不足以克服负载；不能仅凭不转认定通信失败，应先核对内部模式、指示灯、在线反馈和控制报文，再在教学限幅内逐步调整。

证据要分层：有效反馈说明接收与解包成立；邮箱提交只说明帧已交给外设；完成发送说明得到了总线 ACK；实际转动与反馈变化进一步证明目标电机执行。ACK 可能来自其他节点，不能单独证明目标电机执行。

试验结束先 STOP，再结束运行；撤销给定不保证轴立即停止，也不能用暂停 CPU 替代停止命令。
