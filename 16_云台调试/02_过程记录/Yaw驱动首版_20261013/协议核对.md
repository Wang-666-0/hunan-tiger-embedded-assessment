## MIT 控制报文

发送：CAN1标准数据帧，ID=`0x001`，DLC=8。字段按手册第35～36页定义：

| 字节 | 内容 |
| --- | --- |
| D0 / D1 | 位置16位：高8 / 低8 |
| D2 | 速度12位中的高8位（bits11:4） |
| D3 | 高4位=速度bits3:0；低4位=KP bits11:8 |
| D4 | KP bits7:0 |
| D5 | KD bits11:4 |
| D6 | 高4位=KD bits3:0；低4位=`t_ff` bits11:8 |
| D7 | `t_ff` bits7:0 |

首版采用MCU位置PID与速度阻尼，MIT内部KP/KD为0，只发受限`t_ff`。MCU初始参数KP=0.35 N·m/rad、KI=0 N·m/(rad·s)、KD=0.015 N·m·s/rad；MCU请求限制±0.03 N·m，发送层再将12位力矩编码限制为2042～2053，反映射绝对值≤约0.026862 N·m。I54是MCU请求值，尚未经过最后的编码限制。这些数值均不能描述成已验证实际电流限制。

## 固定控制命令

以下8字节均发往标准ID1，不开放泛用任意动力帧。

| 含义 | 数据 |
| --- | --- |
| 进入电机控制模式 | `FF FF FF FF FF FF FF FC` |
| 退出电机控制模式 | `FF FF FF FF FF FF FF FD` |
| 设置电机当前位置为零点 | `FF FF FF FF FF FF FF FE`；首版禁止发送 |
| 清除电机错误 | `FF FF FF FF FF FF FF FB`；首版不自动发送 |

上电Yaw请求及监测均关闭，`YawBackend_Init`不主动发送`0xFD`或`0xFC`，不能据此认定电机自身已失能。`YAW ON`仅在遥控CH5 OFF、摇杆中位及安全条件满足时进入准备，从此开启固定失能命令周期监测；尚无反馈也可以接受准备请求，目的是失能命令后获取反馈。进入实际使能还必须取得新鲜、静止、失能反馈，并进行人工CH5 OFF→中档解锁。MCU复位后监测再次关闭，复位期间及复位后的电机实际停机行为仍未验收。

若本机在失能命令后不提供反馈，首版保持 `online=0`，不自动尝试 `0xFC`；需要用户回传状态，再按本机表现调整验证方法。发送入硬件邮箱 / CAN ACK、反馈失能以及机械停稳是三个不同证据，不能互相替代。

开始监测后，`YAW OFF`、`STOP`、遥控撤权及故障走失能停机路径。`YAW OFF`明确清除`requested`；`STOP`保留准备请求但总撤权，并设置新的人工OFF→ON解锁屏障。收到停止请求之后的新失能反馈，且反馈速度≤6°/s时才清`stop_pending`；这个速度判据受量化影响，必须另外观察机械静止。参考捕获还要求位置连续静止至少20 ms、至少两个样本，以及状态/温度正常。首版的软件参考角捕获由MCU完成，`YAW ZERO`不发送`0xFE`，不改变电机保存零点。

## MIT 反馈报文

手册第39～40页：反馈ID由 Master ID 设置，默认0。首版接受 CAN1标准数据帧、ID0、DLC8，再按载荷中设备ID1匹配Yaw，不把所有CAN1帧计数当作Yaw在线。

| 字节 | 解码 |
| --- | --- |
| D0高4位 | 驱动状态 / ERR |
| D0低4位 | 电机CAN ID；本机为1 |
| D1 / D2 | 位置16位，高8 / 低8 |
| D3、D4高4位 | 速度12位：`(D3 << 4) | (D4 >> 4)` |
| D4低4位、D5 | 力矩12位：`((D4 & 0x0F) << 8) | D5` |
| D6 | 驱动温度，`int8_t`有符号℃ |
| D7 | 电机温度，`int8_t`有符号℃ |

第40页正文另有“ID取低8位”的表述，且两个温度都标成“驱动温度”；本机ID1不涉及低4/低8位扩展歧义，按第39页字段表解包，D6/D7分别对应驱动及电机温度。手册示例含不完整C类型和赋值写法，不直接复制示例函数。

| 高4位数值 | 含义 | 首版处理原则 |
| --- | --- | --- |
| 0 | 失能 | 准备及停止状态反馈 |
| 1 | 使能 | 活动会话反馈 |
| 8 / 9 | 超压 / 欠压 | 故障撤权 |
| 10（A） | 过电流 | 故障撤权 |
| 11（B） | MOS过温 | 故障撤权 |
| 12（C） | 电机线圈过温 | 故障撤权 |
| 13（D） | 通讯丢失 | 故障撤权 |
| 14（E） | 过载 | 故障撤权 |

反馈时间戳使用CAN接收时刻，不把旧队列帧处理时刻当作反馈刚收到。有效反馈年龄达到100 ms故障撤权；连续角度、方向、跨边界行为和状态变换均仍要在本机验证。

## 量化与零输出

浮点映射按端点统一处理：`uint = (x - min) / (max - min) * ((1 << bits) - 1)`，输出前限幅，接收按同一满量程除数反映射。位置用65535，速度、力矩、KP/KD用4095。

手册第36～37页示例发送使用`(1 << bits)`，第40页接收使用`((1 << bits) - 1)`，边界不完全一致；首版不照搬这个示例差异。协议自检需覆盖端点、零点量化及打包/解包位序。

| 字段 | 本机理论量化步长 |
| --- | --- |
| 位置 | `2 × 3.141593 / 65535`≈0.00009588 rad≈0.005493° |
| 速度 | `400 / 4095`≈0.09768 rad/s≈5.597°/s |
| 力矩 | `20 / 4095`≈0.004884 N·m |

12位对称力矩范围有4096个编码，零位于两编码之间：最近零编码映射为约±0.002442 N·m。MCU请求限幅±0.03 N·m时，发送层保留的2042～2053共有12个离散编码，最大反映射绝对值约0.026862 N·m；速度字段也具有约5.597°/s步长，不能根据量化后的“0°/s”单独判断电机完全静止。这些是由当前量程计算的编码分辨率，不是实物传感器精度。

## 软件故障位与恢复

I62及`YAW STATUS`的`FAULT`为同一个位掩码，多个故障按位相加。

| 位值 | 定义 |
| --- | --- |
| 1 | 反馈缺失 / 超时 |
| 2 | 数据非法 |
| 4 | 驱动状态故障 |
| 8 | 驱动≥60℃或电机≥70℃ |
| 16 | 反馈绝对速度>60°/s |
| 32 | 位置反馈跳变 |
| 64 | 相对参考角超出±8° |
| 128 | CAN故障 |
| 256 | 控制间隔>10 ms |
| 65536 | 使能确认超时 |
| 131072 | 使能 / 力矩发送失败 |
| 262144 | 运行中意外失能 |

使能确认须来自发送使能命令之后的新反馈，状态为1；超过100 ms未确认即撤权。活动时收到状态0，按意外失能撤权。两项后端故障65536 / 262144需人工`YAW OFF`，新鲜、失能且静止的反馈、停止确认完成，再`YAW ON`，最后新的人工CH5 OFF→中档；不会通过反复ON自动清除。131072发送失败及CAN故障当前锁存，需要排查后MCU复位；复位不等于电机停机验收完成。

## 软件边界与待验证事项

- Yaw控制2 ms、CAN10 ms、FireWater50 ms；目标±5°、相对参考位置硬边界±8°，正常模式手动目标变化速度进一步限制到±10°/s。CH7±30°仍是请求接口；30°正式阶跃在后续扩大范围和保护验证后开展。
- `APP_MOTOR_DRIVERS_IMPLEMENTED` 的泛用动力门禁继续关闭；Yaw只能通过本轮专用ID1、固定命令及受限MIT给定接口发送，既有摩擦轮CAN2限制和停止路径保留。
- 原摩擦轮6000rpm / 42000ERPM、各2A请求限制、原PI/滤波/斜坡/方向/遥控分配保持；Yaw无需依赖CH6摩擦轮ON来运行。
- `CAN Timeout=20000`的单位及本机真实停机效果未知。反馈超时保护要求MCU仍在正常执行；MCU掉电、卡死或CAN断路时的驱动端停止，需要后续实机验证，不写成首版已经解决。
- 未取得Yaw本轮实物通信、使能、失能、反馈掉线、失联、实际限幅、方向、参考角、机械限位或闭环结果。用户接线完成的反馈不替代这些验证。
- 不声明30°阶跃≤250 ms或误差/超调≤0.2°达标。当前50 ms显示频率不能完成正式时序指标测量。
