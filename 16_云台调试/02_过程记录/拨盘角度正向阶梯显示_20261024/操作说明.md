# 拨盘 50ms 连发与 VOFA 角度显示

本次直接修改当前 VS Code 工程，拨盘版本为 `C610_PHASE_50MS_V1H`。

## 连发行为

- 按住连发时，首发立即提出请求，之后按 **50ms / 20Hz** 节拍提出新请求。每次被控制器接受后，目标角度增加一发的步距，默认拨盘输出轴 **40°**。
- 角度环、速度环仍在原来的 **2ms 控制任务**中随新反馈更新；CAN 电流指令仍为 2ms 周期。50ms 是目标推进节拍。
- 小于等于一个控制周期的迟到沿用原定时间表，防止每次迟到都向后累积。实际事件时间受任务调度影响，正常抖动下相邻间隔可能为 48～52ms。
- 迟到超过 2ms 时只提出一次请求，下一次从当前时刻再等待 50ms，避免补发积压请求。
- 沿用原来的连发速度前馈、位置误差修正和松手收尾。并未要求每个 40° 边界都停转、稳定后再发下一发。
- 实际轮速未就绪或已有两发尚未越过边界时，新请求仍会拒绝，不会积压无限目标。松手取消多余的前瞻目标，完成当前边界；故障按原逻辑停止。

## 在 VOFA 看目标角度和实际角度

重新烧录后，在 VOFA 串口发送框依次发送，每条带换行：

```text
FEEDER ANGLE VIEW
TELEM ON
```

使用现有 FireWater 数据引擎，串口仍为 **921600 / 8N1**，波形每 **5ms** 更新。新建自己的“拨盘角度”标签页，曲线绑定：

| 通道 | 含义 | 单位 |
| --- | --- | --- |
| I0 | 实际拨盘输出轴累计角度的相反数 | ° |
| I1 | 已接受的目标拨盘输出轴累计角度的相反数 | ° |
| I2 | 实际电机转子转速 | rpm |
| I3 | 控制器目标电机转子转速 | rpm |
| I18 | 正在运动 | 0/1 |
| I19 | 故障位 | 位掩码 |
| I21 | 累计接受请求数 | 次 |
| I22 | 编码器确认完成数 | 次 |
| I23 | 拒绝请求数 | 次 |

VOFA 的 I0 和 I1 在串口输出时统一取相反数；默认安装方向下，目标以 `0、40、80、120…°` 向上形成阶梯，每 50ms 提出一个新目标，每发 40°，两次目标更新之间保持不变。I0 同样改为对应的正向实际角度。角度连续累计，不在 360° 处折返，初始零值打印为 0。I1 使用已接受的离散目标边界，原位置环内部的平滑参考、PID、电机方向均保持原设置。实际机械短暂反向时仍如实反映。

`FEEDER VIEW`、`TELEM FEEDER` 和 `TELEM FEEDER ANGLE` 都能切换到相同的 39 通道角度数据流。原有通道顺序兼容。

切换其他视图：

```text
FEEDER SPEED VIEW
WHEEL VIEW
PITCH VIEW
YAW VIEW
```

每次选择所需标签页后，再发送对应的 VIEW 命令；切换 VOFA 标签页本身不会切换下位机数据。VIEW 只切换显示。

## 运行与核对

遥控运行方式保持原习惯：安全关闭状态完成原有准备；CH5 中档进入普通模式，CH6 高档选择连发并等待摩擦轮稳速，CH8 从中档释放位置切到高档启动，回中档结束连发。实际准备、轮速和遥控健康许可仍必须满足。

```text
FEEDER INFO
FEEDER RESULT
```

版本应显示 `C610_PHASE_50MS_V1H`，结果中的 `REQUEST_MS|50` 是请求周期，`RATE_HZ` 和 `CONT_DONE` 来自编码器实际跨过角度边界的统计。请求 20Hz 不代表实机已经达到 20Hz。

```text
build/Gimbal_Control/Gimbal_Control.hex
```
