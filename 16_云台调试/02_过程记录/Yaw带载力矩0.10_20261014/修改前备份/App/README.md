# App 分文件说明

沿用上一考核：业务文件平铺在 App，模块使用配对 .c/.h，统一配置放在 `app_config.h`。main.c保留外设初始化；freertos.c调用 `AppTasks_Create`，业务逻辑通过模块接口运行。

当前增加GL60Ⅱ Yaw首版`GL60II_PID_BENCH_V1`：四组配对模块、±5°目标、MCU位置PID及USART1参数热调，FireWater默认70通道。原6000rpm摩擦轮算法和会话`.c/.h`保持原样，共同CAN模块扩展专用Yaw发送，Pitch / 拨盘实际驱动仍未加入。分轮步骤见[Yaw首版与VOFA调参](../../../01_学习笔记/Yaw首版驱动与VOFA调参_20261013.md)。

Keil/EIDE当前磁盘清单均包含21个App源文件，两者完整清单均58个且一致；新增`gl60_ii.c`、`yaw_controller.c`、`yaw_backend.c`、`yaw_console.c`及各自头文件。之前EIDE写回旧分组的问题已由用户处理，重新构建时核对新增四个源文件已经纳入App分组。本轮AC5完整构建57C+1汇编、0错误、0警告，实物结果待用户反馈。控制任务独占AppLogic，遥控/故障快照、逻辑保护和CAN提交在同一短临界区完成；不在临界区阻塞发串口。受限会话、速度环及Yaw多字段快照也由临界区串行访问。

诊断由电脑显式请求触发，上电只监听CAN，不自动发查询；Yaw上电请求与监测也关闭，第一次安全`YAW ON`后才开始周期发送固定FD失能帧，不宣称上电 / MCU复位已令电机失能。CAN任务独占协议拼接；Console只提交一笔请求并读取结果块。取消、总线错误或1200ms超时会结束查询并撤销挂起发送。两条总线都关闭自动重传，缺ACK时不会持续重发；仲裁丢失也可能造成超时，由用户查明原因后重新采集。读查询不需要遥控解锁，因为不能构造动力命令。

## 关键设计

`operator_armed`表示遥控保护通过；统一`output_allowed`还要求参与运行的执行器反馈健康、停止流程完成且无故障，最终Yaw / 摩擦轮各自决定发送许可。Yaw已请求且CH6关闭时，Yaw独立就绪不要求摩擦轮上电；共同运行则两者均须健康。摩擦轮CAN许可仍要求双轮已准备且CH6开启。当前70/71均非负、各<=2000mA，极性按用户最新确认保留。原速度算法、参数与保护保持不变：目标42000ERPM（按原7对极配置估算6000rpm），20ms且有新STATUS1才更新PI；双轮积分和滤波独立，目标42000ERPM/s爬升，44100/42000软区间。任一轮>46200ERPM、反馈电流绝对值>3A、FET≥60℃或反馈失效均双轮锁停。

Yaw必须先安全CH5 OFF下`YAW ON`准备，取得停止后的失能、静止反馈，再人工新的CH5 OFF→中档才发FC使能。使能需100 ms内新的状态1反馈确认；反馈年龄≥100 ms、状态故障、位置超界、速度/温度/时序异常及意外失能均撤权。MCU控制2 ms、CAN10 ms，PID初值0.35/0/0.015，MIT内部KP/KD为0；输出请求±0.03 N·m，发送层编码2042～2053，反映射≤约±0.026862 N·m。正常模式手动目标变化限±10°/s，串口TARGET只在活动且有许可时接受。STOP保留请求但重新设置人工OFF→ON屏障，YAW OFF取消请求；ZERO只捕获软件参考，不发FE。驱动端CAN Timeout=20000单位及MCU复位 / 失效时的实物停止尚未验证。

GetNodeCurrent为每个CAN节点生成独立请求；旧GetRequestedCurrent在双轮时表示左轮，单轮时仍表示所选轮，兼容I34及原STATUS。INFO和SPEED只读，SPEED双轮输出两行节点统计；停止清积分、保留本次统计，重新启动才清统计。停止原因记录和COAST_MS/ZERO_MS/LOW_MS用于判断软件为何给零或低速，不能当作实物保护时间。T90_MS记录有效反馈首次达到90%目标的接收时间差；BAND_FIRST_MS记录首次连续500ms入带的确认时刻，未达到为−1，停止保留。软件区间标志不会使flywheels_ready变1，泛用发送关闭，不发SET_RPM或写电调配置。

关闭APP_FLYWHEEL_SPEED_ENABLED回归V2的0.5A、1000/600观察和2000ERPM硬保护；时长非0回归点动；200rpm及1000rpm测试分组显式覆盖旧配置，生产默认是本次6000rpm档。

故障优先于解锁。重复读取同一个遥控快照不算新OFF/ON；故障前排队的帧、故障同毫秒的帧都不能解锁。解除故障不会补发旧单发/连发事件。事件位只在当前控制周期有效，累计序号用于观察，不是待执行队列。

发射必须具有动力许可及真实的双摩擦轮稳速反馈。基础版不制造假反馈，所以上板不会出现单发事件。离线测试注入就绪条件，检查单发不重复、连发最小50 ms间隔、迟到不追赶和互锁撤销。

新配置中CH5下档进入测试并关闭摩擦轮/拨盘；左摇杆单轴方向选择±30°和step_axis，CH7中→下确认一次，松手不取消目标，上档发布step_return_event。这些30°事件仍只发布接口，Yaw首版不执行；本轮先通过串口小角度目标，后续完成方向、参考角及限位验收后再接正式阶跃记录。

正常摩擦轮启停由CH6而非CH1决定。安全CH5 OFF帧自动准备双轮，再新的CH5上→中解锁；CH6中/下开启原速度环，上档正常停机不取消总解锁，未停稳时ON不允许延迟自启。失联CH8上档、STOP及发送故障仍要求人工重解锁。MotorBackend继续适配既有FlywheelJog接口，不修改摩擦轮速度环、会话文件或原限流参数；共享CAN层新增Yaw门禁并保留摩擦轮限制与停止路径。历史点动/映射回归同时设置APP_REMOTE_PROFILE_ASSESSMENT=0，并按原用例关闭Yaw模块。
