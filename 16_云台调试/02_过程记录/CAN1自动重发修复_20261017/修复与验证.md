# CAN1自动重发修复 · 2026-10-17

现场两次运行均记录CAN1 FIRST=LAST=HAL=0x00002000、SOURCE3；最新故障时刻FIRST_MS=924145，CAN1 ERR1、CAN2 ERR0。0x2000是本工程HAL_CAN_ERROR_TX_ALST1，代表发送邮箱1因仲裁失败结束，不是ACK错误或BusOff。原始反馈见[Pitch实机记录](../Pitch实机反馈_20261017.md)。

原Core/Src/can.c关闭CAN1自动重发，实际ST HAL置MCR.NART=1。普通仲裁竞争导致一次失败后触发HAL错误回调，CanBus锁存fault_epoch并撤销输出，Pitch只读查询也被阻止。故障后反馈年龄不断增长，不能用冻结的近零角度判断当前可运行。

本轮生产文件只修改两处：

- `Core/Src/can.c`：CAN1 AutoRetransmission改ENABLE，由硬件在仲裁让位后继续发送。
- `Gimbal_Control.ioc`：CubeMX的CAN1.NART属性同步ENABLE（此配置属性名称不能直接当作硬件NART位值；实际HAL执行后MCR.NART=0）。没有重新生成CubeMX工程。

保留CAN2设置、两路1Mbps、CanBus/HAL错误处理、错误通知、故障锁存及全部邮箱归属/撤权取消流程。ACK、BusOff、队列溢出和遥控过期仍撤权，故障后不自动重启。PID、零点/阶跃条件、±50°范围及既有Yaw/摩擦轮实现保持。本轮没有操作串口、烧录器或实物电机。

原文件备份在`修改前备份`；`修改前哈希.json`保存126个源文件/配置的修复前哈希。`verify_can1_retry.py`核对受保护文件，确认只有上述两个生产文件发生变化，并验证全部回归报告源文件哈希。

验证结果：

- ARM Compiler 5.06、O0完整重新构建64C+1汇编共65源项，0错误0警告。Code81060 / RO-data4908 / RW-data568 / ZI-data34768。见`完整构建.log`。
- 原53组449737项实际ARM C回归，全部完成返回、0失败。包含原Yaw、摩擦轮、遥控保护以及Pitch独立许可、延迟取消和单轴邮箱隔离。见`离线自检.log`、`selftest_results.json`。
- 专项33项：真实Core/Src/can.c与ST stm32f4xx_hal_can.c在Unicorn执行，使用真实头文件和模拟寄存器输入，核对CAN1硬件NART=0、CAN2 NART=1，两路原1Mbps/引脚/IRQ优先级；未完成的仲裁等待不产生完成错误，TXOK后按成功处理；ACK在RQCP未完成时仍进入错误回调，BusOff/被动/警告继续报告；真正完成的ALST仍报告；固定邮箱取消请求仍可写入。见`test_can_registers.c`、`verify_can1_retry.py`、`final_verification.json`。
