# 工程精简审阅与待确认清单

审阅日期：2026-10-25。对象为当前 VS Code / EIDE 工程及其实际编译的 App、Core、测试入口和最近一次链接报告。

本轮先审阅，尚未删除、移动或改写正式源码，未重新编译、烧录或运行电机。此前拨盘独立单发/连发修改仍保留。本文中的删除项需要用户确认后实施。

## 1. 审阅结论

应以“每个模块职责清楚、移除不用的行为和历史分支”为目标，不再限制 C 文件数量。

当前 App 有 10 个 C 文件，共 9,625 行（含注释和空行）。其中 Yaw 1,449 行、电机控制台 1,387 行、系统控制台 1,135 行、Pitch 1,132 行、CAN 1,083 行。之前把多个实现拼到同一文件，减少了文件数量，但没有减少功能、条件分支或模块间依赖。

当前实际功能和历史实验混在一起，是比文件数量更值得处理的问题：

- 现用 CH5～CH8 遥控逻辑与旧遥控配置同时保存在源码中。
- 现用摩擦轮速度 PI 与早期定时低电流试转、开环观察保存在同一状态机中。
- 现用 Yaw 双环与旧单环、实验轨迹及加速度前馈对照代码同时保留。
- 电机业务命令、设备初期读参、CAN 被动抓包和波形格式化混在控制台中。
- `YawCascade` 和 `YawStep` 实际由两轴共用，名称和存放位置容易让人误以为 Pitch 不依赖它们。
- 测试需要从大文件的 `APP_SECTION_BEGIN/END` 标记中抽取逻辑分区；这也是人为合并文件带来的维护工作。

## 5. 本轮推荐保留的功能

- 四类电机现用控制，全部原 PID 数值及运算顺序。
- Pitch 重力前馈、末段/回退刹车和原参数；Yaw/Pitch 归位、阶跃、当前窗口锁另一轴。
- 拨盘独立测试开关及其单发、每 50 ms 连发、每发 40°、真实反馈与目标角度输出；正常双摩擦轮互锁恢复入口。
- 电机使能/停机握手、零点/水平标定、坐标确认、运行反馈时效、失联撤权、故障、限位、堵转、过流和过温检查。它们是现用控制的一部分。
- 现用串口调参、各 VOFA 视图和通道顺序；现有带标记的显示演示单独收纳，真实反馈/控制/成绩保持独立。
- Pitch 的可选全程 SHAPE/SHAPEV 和首次到位/回退详细快照，先保留。默认关闭不等于无人使用；以后若确认不用，可另批清理，不把它们与仍在使用的刹车一起删掉。
- 现用功能的离线测试。它们不在 EIDE 正式源列表中，不占 MCU Flash；没有必要为了固件体积删除测试目录。

## 6. 更合适的目录呈现

推荐按职责整理为五组，配置文件仍在 App 根目录。下面是职责示意，实施时按清理后实际代码划分，不规定文件数量：

```text
App/
  app_config.h       调参、功能配置和固定协议常量
  system/            任务、启动、安全与遥控业务状态机
  drivers/           CAN、USART/iBUS 接收和电机协议编解码
  control/           两轴共用串级 PID、真实阶跃统计
  motors/            yaw / pitch / feeder / flywheel 控制器与后端
  console/           命令分发、各电机命令、VOFA 格式化与显示演示
```

具体原则：

1. 算法与硬件后端分开；后端管理会话和 CAN，算法只处理输入、状态与输出。避免任意文件既有纯数学、硬件许可，又有串口解析。
2. 共用双环和阶跃统计独立呈现，不再藏在 Yaw 大文件里。Yaw/Pitch 会话和协议保持各自边界，不强行抽象为万能电机状态机。
3. 控制台保留清晰的系统/电机命令入口。波形格式化从命令解析中分开，重复的别名只做一次规范化。保留 VOFA 既有索引，不因删诊断字段让后面的通道整体移位。
4. 头文件与对应实现放一起，对外仅暴露真正需要的接口和类型；内部辅助函数保留 `static`。少量工具函数可留头文件，大段显示实现移到显示模块。
5. `app_config.h` 按“调度与模式、遥控、Yaw、Pitch、拨盘、摩擦轮、通信、固定协议常量”分区，不再用“原某文件”作为主要分类。维持唯一宏入口、明确单位和编译默认值/RAM 调参区别。
6. 每个文件开头说明用途、主要入口、调用方和单位。函数注释解释约束与原因，历史调参过程归档，避免在正式实现中堆积多轮修改说明。
7. 模块恢复独立编译后，测试直接编译正式实现；相应移除仅为十文件拼接服务的分区抽取机制，减少标记与映射的同步维护。
