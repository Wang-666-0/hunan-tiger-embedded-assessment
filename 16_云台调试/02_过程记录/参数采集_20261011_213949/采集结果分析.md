## DM3507 / Pitch

| 读取项 | 实机配置读值 | 后续用途 |
| --- | --- | --- |
| ESC_ID / MST_ID | 2 / 2 | MIT接收和反馈帧ID均为0x002；相同本身不构成配置故障，仍要与GL命令/反馈ID核对 |

| PMAX / VMAX / TMAX | 约π / 200 / 10 | 位置、速度、扭矩双向映射量程；不能当成机械安全限位、允许速度或额定扭矩 |

| can_br | 4，1Mbps | 与当前CAN1设置及有效回包一致 |
| TIMEOUT | 0 | 未能从现有资料确认零值的特殊行为，不能据此保证断通讯自动停机 |
| sub_ver | 50 | 原始版本字段保留，不据此认定硬件代次 |

特别注意：现行SDK的DM3507默认量程与这台实机不同，正式代码应采用实读的PMAX/VMAX/TMAX。当前只有参数响应，没有本机位置、速度、扭矩和ERR的运行反馈；还需核验方向、零点、软限位、限流和停机行为。

TIMEOUT的文档单位是50µs计数周期，且只在使能时生效；零值究竟禁用还是具有其他行为，应按本机固件说明或受控低功率断通讯测试确认。资料依据为[官方DMTool说明书](D:/Project/27电软正式批考核/16_云台调试/03_参考资料/02_Pitch_DM3507/上位机/DMTool上位机软件说明书.pdf)及[官方SDK](https://github.com/dmBots/motor-sdk/blob/main/Python%E4%BE%8B%E7%A8%8B/u2can/DM_CAN.py)。

两台CAN均配置1Mbps，应用为UART，UART波特率115200。ID70的STATUS1/4/5为500Hz、STATUS2为5Hz；ID71的STATUS1为50Hz、STATUS2/4/5为5Hz，原始计数变化与配置一致。这是反馈频率差异，不能当成采集丢包。后续闭环与反馈超时阈值应分别适配。

两台GET_VALUES尾部的通信超时标志为1，符合本次未持续发送控制命令的静止状态，不是故障码。当前无故障与静止数据不能替代运动、负载、方向和停机验证。

需要核验的实际问题：

1. 负电机温度不能作为真实温度。优先检查是否有温度传感器、接线和类型是否匹配。未接或输入异常可导致很低的NTC换算值，但仅凭本次数据不能断定是哪一种原因。
2. 极数、传动比、轮径都是当前电调配置，不是本次自动辨识结果，也不能仅凭GET命令证明已持久化到Flash。确认摩擦轮是否直驱，或有皮带/齿轮传动后再换算6000rpm。
3. 若实际极对数为7且直驱，轮速6000rpm对应42000ERPM；若实际为电机:轮=3:1，则需要126000ERPM，超过当前配置的100000ERPM上限。这个差异说明传动关系必须先核对，不能直接把配置中的3代入驱动代码。
4. 电池节数配置为3、低压截止开始/结束为10/8V，而当前输入约25V。应确认动力源是电池还是稳压电源；若使用实际6S电池，应进一步核对相关低压配置。当前读取不能替代电源规格确认。

## C610 / 拨盘与GL60Ⅱ / Yaw

C610收到CAN2标准帧0x205，与ID5反馈一致。本次转子角度原始值4102、转速0、转矩反馈原始值16；末两字节为保留字段。现在能确认反馈在线，但无法从静止快照推导每发步距、方向、堵转阈值或转矩的物理单位。无需再查所接电机的商品型号；后续标定每发累计转子编码器增量即可。

本次未取得GL60Ⅱ运行反馈，且采集工具未向它发送参数查询或使能命令。因此不能判定它损坏或离线。GL的模式、命令/反馈ID、量程和固件配置仍缺，应优先通过厂家上位机读取；[官方产品页](https://www.cubemars.com/cn/product/gl60-II-kv28-gimbal-motor.html)提供上位机和手册，并说明白色三针接口用于上位机通信。实物针序仍应按手册与接口标注核对。
