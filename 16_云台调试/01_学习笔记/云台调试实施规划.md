# 云台调试实施规划

## 1. 先明确验收口径

图二要求 Pitch 30°阶跃不超过 300 ms、Yaw 30°阶跃不超过 250 ms，稳态误差和超调均不超过 0.2°。考核图没有定义“响应时间”是上升时间还是调节时间；在得到正式解释前，本方案采用更严格且可复现的临时口径：目标在一个控制周期内直接从 0°跳到 +30°或 -30°，从目标跳变时刻开始计时，到反馈进入目标 ±0.2°并连续保持至少 50 ms 为止。最终记录中同时保存首次进入时间、保持时间、峰值、尾段平均误差和尾段最大绝对误差。

阶跃验收时不得使用目标斜坡、S 曲线或轨迹发生器。电流限幅、积分抗饱和、反馈滤波和安全软限位可以保留，但必须记录参数。正、负方向各至少测试 5 次，采用最差结果判断，而不是只保存最好的一次。

还需向考核方确认两点：30°是电机输出轴角度、云台机械角度还是相对惯性姿态角；“云台调试时不能相互交流”的具体执行边界。本工程先把后者作为考核纪律记录，不把它转化成未经确认的软件协议限制。

## 2. 总体软件结构

一套固件同时包含全部功能，建议采用以下数据流：

```text
i-BUS输入 ──> 遥控快照 ──> 保护/模式状态机 ──> 目标管理器
                                                │
CAN1反馈 ──> GL60/DM驱动 ──> 两轴状态 ───────────┤
实物IMU ──> 带时间戳姿态/角速度 ────────────────┤
CAN2反馈 ──> VESC/C610驱动 ─> 发射机构状态 ──────┤
                                                ▼
                         Yaw/Pitch控制 + 摩擦轮控制 + 拨盘控制
                                                │
                              统一安全输出门禁与CAN发送
                                                │
                                  CAN1 / CAN2 + 日志缓冲
```

模块按职责拆分，不让某个电机驱动直接读取遥控器：

| 模块组 | 建议模块 | 职责 |
| --- | --- | --- |
| 输入 | `ibus`、`remote_input`、`remote_mapper` | 接收、校验、时间戳和逻辑动作映射 |
| 保护 | `safety_manager` | 上电锁定、急停、失联、反馈超时、越界、堵转和人工重新解锁 |
| 总线 | `can_bus`、`can_frame`、驱动分发 | 同时处理 CAN1/CAN2、标准/扩展帧、可变 DLC、过滤和每路错误状态 |
| 驱动 | `gl60`、`dm3507`、`vesc_can`、`c610` | 只负责协议编解码、单位换算和反馈新鲜度 |
| 估计 | `gimbal_feedback`、实际IMU驱动、`mahony` | 零点、连续角度、坐标方向及可选的IMU角速度；4.8.1装配待核对 |
| 控制 | `gimbal_controller`、`flywheel_controller`、`feeder_controller` | 两轴串级环、摩擦轮速度与拨盘位置步进 |
| 调度 | `app_tasks`、`app_logic`、`motor_backend` | 周期任务、模式切换和模块组合 |
| 验收 | `step_test`、`telemetry` | 真实阶跃触发、RAM 日志、串口输出和指标计算 |

所有输出先生成“请求”，最后统一经过 `safety_manager`。任何模块都不能绕过门禁直接发送非零给定。

2026-10-11已落地第一版基础工程，App下采用上一任务的平铺 .c/.h 格式。当前实现输入、保护、目标事件、双CAN接收与遥测；驱动、估计、闭环及阶跃指标仍待补。基础控制周期2 ms，遥控解析2 ms，在线遥测50 ms。下文的快速闭环、前馈和实机验收是下一阶段目标。

## 3. 阶段一：遥控保护先做、先验收

状态建议为 `BOOT → SAFE → READY → RUN`，任何故障进入 `FAULT`。上电、复位或故障恢复后都停在 SAFE；只有收到新的有效遥控帧、全部关键反馈在线、操纵量回中，并观察到一次明确的“关闭→开启”动作后才能进入 RUN。

必须覆盖：

- i-BUS 100 ms 无新鲜合法帧、UART 错误或队列溢出；
- 接收机仍发 Failsafe 帧时，独立许可通道落到停止值；
- CAN1/CAN2 错误、关键电机反馈超时、控制周期严重迟到；
- 云台软限位、驱动器温度/故障、拨盘堵转；
- 人工急停和主控复位。

故障时同时撤销两轴输出、摩擦轮目标和拨盘发射请求，并清空尚未执行的单发/连发事件。恢复链路不得自动重启，必须先回安全档再人工重新解锁。不同驱动的“安全输出”要通过手册和实机确认：禁能、零电流、零转速和制动的机械结果并不相同。

保护验收通过前，不进入 PID 调参。专项测试至少包含：关闭发射机、拔接收机信号、让帧停止、CAN 反馈断开、主控复位、链路恢复但未重新解锁。

## 4. 阶段二：协议和测量打通

### CAN1：Yaw 与 Pitch

旧 GM6020 驱动不能通过修改 ID 复用为 GL60 或 DM3507。先在电机悬空、低限幅条件下分别验证：使能/失能、控制模式、命令 ID、反馈 ID、量程、字节序、方向、零点、反馈频率和超时行为。

达妙官方 SDK 显示，DM 系列的 MIT、位置速度、速度模式可分别使用 `SlaveID`、`0x100 + SlaveID`、`0x200 + SlaveID`。所以“ID 2”并不等于所有控制模式都向 CAN ID 0x002 发帧；MasterID、PMAX/VMAX/TMAX 和固件兼容使能也要从实物读取。

用户已确认 Yaw 为 GL60Ⅱ，CAN1设备编号1。后续按[CubeMars GL60Ⅱ 官方下载页](https://www.cubemars.com/cn/product/gl60-II-kv28-gimbal-motor.html)的 GLⅡ 驱动说明实现；先读取本机驱动固件、模式和配置，不混用旧GL手册或其他厂家的MIT量程。两台设备共用CAN1前，还要确认同一波特率且仲裁ID不冲突。

### CAN2：VESC 与 C610 混合总线

C610 固定使用 1 Mbps，因此 CAN2 应规划为 1 Mbps，并在 VESC Tool 中把两只 N630 的实际 VESC 固件配置成相同波特率。上一任务 CAN2 是 500 kbps，不能直接沿用。

VESC 使用 29 位扩展帧，扩展 ID 为 `(command << 8) | node_id`。若 70/71 是十进制节点号，`SET_RPM` 命令 3 对应 `0x346/0x347`，DLC 为 4，载荷是大端有符号 `int32`。命令值是 ERPM，机械 6000 rpm 需要换算：

```text
极对数 p = 磁极数 / 2
ERPM目标 = 摩擦轮机械转速 × 电机转速/轮速传动比 × p
```

不能在极对数未知时直接发送 6000。还需读取 VESC 状态帧验证实际 ERPM、电流、占空比和在线时间，并核对 `SET_RPM(0)`、通信超时和 timeout brake current 的实际停机效果。

C610是电调。ID5的控制帧是标准帧0x1FF、DLC8，电流给定放在DATA[0:1]，其余槽清零；反馈为0x205。负责人已确认无需记住所接电机型号，驱动按C610协议实现；拨盘每发步距可直接标定为累计转子编码器计数，型号和各级减速比不再是编写驱动的前提。

因此驱动路由必须先区分标准帧/扩展帧，再分发完整ID。基础版 `can_bus` / `can_frame` 已支持两条总线和可变DLC，后续通过 `motor_backend` 分发，不能沿用旧工程“只收标准帧、固定DLC8、只使用CAN1”的实现。

## 5. 阶段三：两轴控制与前馈

先逐轴调试，另一轴保持安全失能。步骤如下：

1. 低限幅核对正反馈：正向给定时反馈角度必须正向增长，错误时先修方向和单位。
2. 建立零点、连续角度和软限位；测试反馈跨零、掉线和重新上电。
3. 调速度/角速度内环，使其快速、无持续振荡，再打开角度外环。
4. 外环先 P，随后加入少量 I 消除静差；微分优先使用反馈角速度，避免目标阶跃造成微分冲击。
5. Pitch 尝试重力前馈 `u_ff = K_g sin(theta)`；若电机支持力矩/电流模式，可再加入静摩擦补偿。Yaw 只在有可测负载规律时加入速度或摩擦前馈。
6. 在低角度、小限幅下逐步扩大到 ±30°，最后执行正式阶跃记录。

角度外环优先使用电机输出轴/机械角反馈完成相对阶跃；实物IMU的角速度可用于阻尼或观测。4.8.1原理图有MPU6050及外置IMU FPC，须核对装配，不能默认板载BMI088。六轴IMU的Yaw会漂移，不能单独保证长期0.2°绝对航向。若使用外置BMI088并复用第14项工程，其原配置是200 Hz任务、400 Hz ODR / 47 Hz低通；快环1–2 ms须重新核对ODR、带宽和新鲜时间戳。

## 6. 阶段四：摩擦轮 6000 rpm 与降噪

左右轮分别完成低速方向测试，再共同升速。只有两轮都在线、达到目标并在允许误差带内稳定一段时间，拨盘才可获得发射许可。

降噪按以下顺序排查并保持同一距离、同一背景和同一测速口径记录对比：

1. 摩擦轮动平衡、同轴度、轴承、紧固件、轮间间隙和机架共振；
2. 左右轮实际机械转速和方向是否一致；
3. VESC 电机参数识别、FOC 模式、限流、速度环和开关频率；
4. 目标变化斜率只用于正常启停，6000 rpm 稳态验收仍以最终机械转速为准。

考核没有给出 dB 指标，所以记录相同工况的噪声对比、振动现象和调整项，不凭主观一句“更安静”结项。

## 7. 阶段五：拨盘单发与 20 Hz 连发

设拨盘每转有 `N` 个有效弹位，`G` 为电机转数/拨盘转数：

若不知道N/G，直接测量每发累计转子编码器计数C：位置目标每次增加C；20 Hz所需平均转子转速为 `C × 20 × 60 / 8192 rpm`。以下传动公式可作为交叉验算方式，不要求先查电机名称。

```text
每发电机转角 = 360° × G / N
每发编码器增量 = 8192 × G / N（仅适用于反馈每转8192格的对应电机）
20 Hz所需电机平均转速 = 1200 × G / N rpm
```

单发只消费一次遥控动作的上升沿，动作保持不能重复触发。连发用绝对 50 ms 节拍产生目标，不追赶故障或阻塞期间积压的发射请求。每个位置步进要确认到位，若在限时内未到位且出现低速高电流，则停止、清队列并锁定堵转故障；解锁后也不补发旧请求。

先验算所需电机转速和加速度是否可行，再用实际出弹计数验证 1 秒内 20 发。仅看到软件每 50 ms 改一次目标，不能证明达到 20 Hz。

## 8. 任务和记录建议

候选周期需以反馈实测结果为准：CAN 接收中断只搬运；两轴控制 1–2 ms；遥控状态 5 ms；摩擦轮命令 10 ms；拨盘控制 1–2 ms；在线遥测 20 ms。使用 `vTaskDelayUntil` 或硬件时间戳，所有反馈结构都保存最后接收时刻和序号。

阶跃期间在 RAM 环形缓冲中以控制周期记录目标、实际角度、角速度、控制输出、电机反馈时间戳和保护状态，动作结束后再慢速导出，避免 115200 串口打印扰动快环。在线遥测仅显示必要状态。

完成单模块后还要做整机压力测试：两路 CAN 同时收发、两个云台轴阶跃、两只摩擦轮 6000 rpm、拨盘 20 Hz、遥控和串口同时工作，检查总线负载、队列溢出、控制周期最差值、任务栈余量和 CPU 占用。
