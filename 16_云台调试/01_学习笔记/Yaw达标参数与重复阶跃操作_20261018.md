# Yaw 达标参数与重复阶跃操作（V2N）

固件：`GL60II_FIXED_PID_V2N`。仍使用原工程和 **Ctrl+Alt+D** 编译下载。

## 本次实测结论

用户最后截图的 MCU 遥测为 `I60=218、I61=218、I62=1`，分别对应首次进入 ±0.5°、最终进入并保持的时间、考核结果。因此**这一次 Yaw 的 0→30° 测试满足 250 ms 内稳定在 29.5～30.5° 的要求**。最终保持由原 5 秒测量窗口评估。

这不能代替其它重复试验或 Pitch 的考核。烧录本次修改后，建议同负载、同姿态、同供电连续完成至少 3～5 轮，各轮均检查完整 `YAW RESULT` 的 `VALID=1、FAULT=0、SETTLE05_MS≤250、PASS05=1`。不要只看 `RESP05_MS`，它可能只是第一次经过目标带。旧 `PASS` 使用较严的旧规则，与新考核 `PASS05` 分开。

## 遥控器怎样连续重复测试

保持原解锁、使能和 CH8 规则，CH5 在测试档：

1. **CH7 中位**，左杆仅水平选择 Yaw 正方向，CH3 保持中位；再把 **CH7 拨高位**，发起一次 +30° 阶跃。
2. 可以松开选轴杆。等这一轮完整 **5 秒结束**，读取 `YAW RESULT`。测试期间再次拨高不会开始新一轮。
3. **CH7 拨低位**，执行 HOME 回本次软件零位。目标要回到 0°，实际角度进入 **±0.2°** 并连续静止至少 **20 ms**。实际回零需要运动时间，不能只快速划过低位。
4. **CH7 重新经过中位**，再次选择单轴方向、拨高位，开始下一轮。无需每轮发送 READY，也不要每轮重新设零。

本次修正：若 CH7 已从中位拨高，而左杆还在中心，确认状态会等到单轴选择有效后再发布一次请求。**斜向选轴仍然拒绝并消耗确认**，需要重新经过 CH7 中位；一次有效请求后持续保持高位不会连发。

另一处修正：阶跃起步的静止判断以连续编码器位置、滤波速度和实际 CAN 反馈时间为依据，保留电机原始速度的一致性检查。原始速度在静止时跳动到 ±8.4/±14°/s，不再单独造成频繁拒绝。重新设零、清错、OFF 及故障保护规则未放宽。

## 没反应时看拒绝原因

发送只读命令：

```text
YAW STEP CHECK
```

| WHY 返回值 | 下一步 |
|---|---|
| READY | Yaw 后端具备起步条件；重新经过 CH7 中位、选方向、拨高 |
| WAIT_5S_WINDOW | 上一轮还在测量；看 WINDOW_LEFT_MS，等结束 |
| SEND_HOME_FIRST | 当前目标不是零；CH7 低位 HOME |
| WAIT_ZERO_BAND | 还没实际回到 ±0.2°，继续等回零 |
| WAIT_STILL / WAIT_STILL_HOLD | 有运动或尚未满足连续静止时间 |
| NEED_ZERO / NOT_ACTIVE | 按原上电准备、使能流程处理 |
| FEEDBACK / FAULT | 查询 YAW STATUS、YAW BUS，处理实际故障 |
| REMOTE_OR_OUTPUT_GUARD | 检查原解锁、CH5/CH8 和输出许可 |

`BLOCKS` 可同时包含多个原因；`WHY` 显示优先的一项。拒绝的动作**不会排队自动补发**，满足条件后需要新的确认。遥控有效请求也会返回 `Y|REMOTE_STEP|...|RESULT|...|WHY|...|BLOCKS|...`，可区分已接收、回零和起步拒绝。

`READY` 表示后端条件；`CONSOLE_READY` 额外要求串口 STEP 的遥控中立条件。正在用左杆选轴时，前者为 1、后者为 0 可以是正常情况。串口测试需各杆回中，使用 `YAW STEP 30` / `YAW HOME`，两种入口共用相同后端门禁和 5 秒测量。
