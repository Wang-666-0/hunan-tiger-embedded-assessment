# 摩擦轮双轮1000rpm持续测试

本文保留**DUAL_RPM1000_I1000_V1**历史操作。用户已反馈两轮I29/I30约7000ERPM正常；当前源码已更新为6000rpm快速升速档，操作以[双轮6000rpm与快速升速测试](摩擦轮双轮6000rpm与快速升速测试.md)为准。继续使用原Gimbal_Control工程，不要求逐轮操作或拍摄视频。

目标为两轮各7000ERPM，暂按用户同意的7对极、1:1直驱估算为1000rpm。实际极对数尚未独立确认，所以这是控制档位名称，不能据此填写真实轮速或6000rpm验收成绩。

## 1. 在原工作区构建、烧录

1. 保持CH1回中、CH5 OFF、CH6高位，沿用原测试摆放方式。
2. 在原[VS Code工作区](D:/Project/27电软正式批考核/16_云台调试/Output/Gimbal_Control/MDK-ARM/Gimbal_Control.code-workspace)运行“eide: 重新构建”。确认构建成功，再按Ctrl+Alt+D通过原ST-Link配置烧录。
3. 本版没有新增App源文件；现有Keil/EIDE清单均为54个源文件，包含flywheel_speed.c。无需另建工程或选取独立固件文件。
4. USART1继续115200/8N1，VOFA用FireWater，数据间隔50ms。默认遥测为51通道，原I0～I43的位置保留。

## 2. 核对板上版本

CH1回中、CH5 OFF时发送字符串`WHEEL INFO`并添加换行，预期完整回复：

```text
W|INFO|DUAL_RPM1000_I1000_V1|LEFT_MA|1000|RIGHT_MA|1000|LEFT_SIGN|1|RIGHT_SIGN|1|MS|0|ERPM|9000|ENABLED|1|HOLD_TO_RUN|1|COAST_ERPM|8000|RESUME_ERPM|7000|MODE|CURRENT_PI|POLE_PAIRS_ASSUMED|7|TARGET_RPM|1000|TARGET_ERPM|7000|BOTH|1|FB_MAX_MA|2000
```

若仍回复旧版本，先检查重新构建/烧录输出，完成新版本核对后再开始运动。

## 3. 同时启动两轮

1. CH1回中、CH5 OFF、CH6高位，发送`WHEEL OFF`，等待两轮停稳。
2. 发送`WHEEL BOTH`并添加换行，成功回复`W|OK|BOTH`。这一步只选择双轮，不启动。
3. 继续保持CH5 OFF、CH1回中至少0.5秒；随后CH5 ON，CH1仍保持回中约0.2秒。
4. 沿原先能启动的正向推住CH1，两轮一起运行。先观察约2秒；若方向、振动和运行正常，可继续保持至总计约8秒。不需要在转动期间反复发送查询。
5. 回中CH1并把CH5置OFF即可停给定。若出现明显异常或故障，直接用这个动作停止，不继续保持运行。

只要遥控正向请求、许可和反馈保持正常，软件不会按时长结束。再次运行需要两轮停稳后CH5 OFF回中→ON，再推住CH1。回中、撤权或硬故障后不会自动重启。

`W|ERROR|UNSAFE`表示选择条件尚未满足：检查CH5 OFF、CH1中位、遥控新鲜、两轮停稳、反馈正常，并确认先做了WHEEL OFF。`W|ERROR|DIAGNOSTIC`时先发送`DIAG OFF`，再按上述步骤选择。

## 4. 停止后复制运行记录

分别发送`WHEEL SPEED`和`WHEEL STATUS`，均添加换行。将所有`W|...`行复制出来即可；SPEED在双轮运行后输出三行：一行会话摘要、节点70与71各一行统计。

```text
W|SPEED|LAST_WHEEL|3|ACTIVE|0|STOP_REASON|...|FAULT|...|SAFETY|...|LEFT_MA|0|RIGHT_MA|0
W|SPEED_NODE|70|TARGET_ERPM|7000|RAMP_ERPM|...|FILTER_ERPM|...|RPM_EST|...|AT_LIMIT|...|IN_BAND|...|RUN_MS|...|PEAK_ERPM|...|BAND_MAX_MS|...|LIMIT_MS|...|COAST_MS|...|ZERO_MS|...|LOW_MS|...
W|SPEED_NODE|71|TARGET_ERPM|7000|RAMP_ERPM|...|FILTER_ERPM|...|RPM_EST|...|AT_LIMIT|...|IN_BAND|...|RUN_MS|...|PEAK_ERPM|...|BAND_MAX_MS|...|LIMIT_MS|...|COAST_MS|...|ZERO_MS|...|LOW_MS|...
```

省略号仅是字段示意，实机会回复数值。停止会清积分、给定和区间标志，但保留本次时长、滤波末值、峰值与累计统计；重新启动才清空统计。停止后的FILTER_ERPM/RPM_EST是最后控制样本，实时停转看STATUS的左右原始ERPM。

- RUN_MS：本次会话从启动到最后一次控制调用的时间；不是已经量化的保护响应时间。
- PEAK_ERPM：有效STATUS1报告过的原始绝对值峰值，不经过低通；20Hz遥测不一定捕捉每次峰值。
- BAND_MAX_MS：原始及滤波速度同时在7000±350ERPM内的最长软件连续区间；IN_BAND在持续500ms后置1。
- LIMIT_MS：给定达到本轮1A上限的累计控制时间。
- COAST_MS / ZERO_MS：软件软滑行状态 / 零给定的累计时间。
- LOW_MS：目标斜坡已到7000，原始速度低于1400ERPM且先前给定为正的累计时间，用于识别“活动仍为1但反馈速度很低”。

这些统计不代替电流实测、机械停转计时或未知电机模型。若仍转一会儿停下来，说明大概是在第几秒、哪一轮，并给出上述文本；不需要视频。

## 5. 需要时查看VOFA

| 通道 | 当前含义 |
| --- | --- |
| I29 / I30 | 左 / 右原始ERPM；两轮目标绝对值各约7000 |
| I31 / I32 | 左 / 右反馈电机电流mA，反馈分辨率100mA |
| I33 | 选择：0关、1左、2右、3双轮 |
| I34 / I44 | 双轮时左 / 右给定mA，各0～1000 |
| I35 / I36 | 会话活动 / 故障位；运行期应为1 / 0 |
| I37 / I38 | 双零停止待重试 / 可触发启动 |
| I39 / I40 / I41 | 主控制器的斜坡目标ERPM / 滤波ERPM / 按7对极估算rpm；双轮时为左轮 |
| I42 / I43 | 主控制器给定到限 / 软件速度区间标志 |
| I45 / I46 / I47 | 右轮斜坡目标ERPM / 滤波ERPM / 按7对极估算rpm |
| I48 / I49 / I50 | 右轮给定到限 / 右轮软件速度区间标志 / 停止原因 |

停止原因：0无、1CH1请求消失、2输出许可撤销、3摩擦轮硬故障、4外部Stop接口、5定时结束（历史点动模式）、6启动时两轮未停稳。外部停止的具体来源可结合SPEED摘要的SAFETY及原I14保护原因判断。故障位可叠加：1反馈失效、2坏帧、4温度、8电流、16超速、32CAN故障代次、64外部/发送故障。

## 本档控制与保护边界

左右均保留已确认的正给定，各用独立PI、滤波和积分。目标1750ERPM/s爬升，无滑行或反馈空窗时约4秒到7000；电流增加不超过5mA/ms，降低可立即执行。只发受限SET_CURRENT，每轮最多1A，不使用SET_RPM，也没有写电调参数。

单轮原始速度到8000ERPM暂时零电流滑行，降到7000恢复调速；另一轮继续独立运行，I35保持1。任何一轮严格超过9000ERPM、反馈电机/输入电流绝对值超过2A、FET达到60℃、坏帧或反馈失效，均结束双轮会话。STATUS1/4新鲜度仍为100/600ms，原CH5、CH6、遥控、UART/CAN及控制迟到保护继续参与许可。

1A是主控给定限制，2A是收到反馈后判断的阈值，不能等同于电调自身的硬电流限幅；电调保存的±20A仍未修改。0mA为滑行，不能保证机械瞬停。软件持续发命令不保证未知负载下已经达到稳定1000rpm，需本次实物记录确认。完整6000rpm、降噪、保护时间和拨盘就绪仍未验收。
