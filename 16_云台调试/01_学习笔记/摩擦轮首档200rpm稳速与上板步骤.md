# 摩擦轮首档200rpm稳速与上板步骤

本文保留SPEED_R200_L500_R500_V1的单轮200rpm历史操作。当前源码已按用户请求更新为双轮1000rpm档，操作以[双轮1000rpm持续测试](摩擦轮双轮1000rpm持续测试.md)为准，继续使用原Gimbal_Control工程。

首档控制目标是1400ERPM，暂按用户同意的7对极、1:1直驱估算为200rpm。实际极对数尚未独立验证，本档也尚未取得实物稳速结果；6000rpm和降噪仍待后续逐档测试。

## 本档做什么

- 一次只选一轮；左右方向保持用户已确认的正给定。
- 主控用ERPM反馈做受限电流PI调节，目标从0以700ERPM/s升至1400，约2秒。
- 电流给定仍为0至500mA，增大最多5mA/ms；减小可立即执行。
- 控制周期20ms且有新STATUS1才更新，反馈低通时间常数60ms；重复帧不重复积分，长间隔不追补积分或斜坡。
- 所选轮原始ERPM绝对值到1600暂时零电流滑行，降到1400恢复调节；滑行active仍为1。
- 严格超过2000ERPM、反馈电流超过1A、FET达到60℃、反馈失效及原遥控/CAN保护仍会结束会话。硬保护使用原始反馈，不受滤波影响。
- 回中、CH5 OFF、CH6低位、STOP或故障均停机，积分清零；再次启动仍需OFF回中再ON。零电流为滑行，机械停转需要时间。
- 当前只发受限SET_CURRENT，不使用SET_RPM；完整驱动和拨盘就绪仍关闭。

## 1. 重新构建和烧录

1. CH1回中、CH5 OFF，发送WHEEL OFF并带换行；等两轮停稳后断开电机动力。
2. 打开原[VS Code工作区](../Output/Gimbal_Control/MDK-ARM/Gimbal_Control.code-workspace)。当前EIDE出现自动写回旧分组：在EIDE的App右键添加`App/flywheel_speed.c`并保存，确认App分组共有17个.c；如果界面已经有此文件则保留一份即可。
3. 执行“eide: 重新构建”，确认成功后Ctrl+Alt+D，通过现有ST-Link/SWD烧录。继续使用工程已有下载配置。
4. 复位后连接USART1，VOFA为115200/8N1、FireWater，数据间隔50ms；CH1中位、CH5 OFF。发送WHEEL INFO，必须看到下面的版本与字段。

```text
W|INFO|SPEED_R200_L500_R500_V1|LEFT_MA|500|RIGHT_MA|500|LEFT_SIGN|1|RIGHT_SIGN|1|MS|0|ERPM|2000|ENABLED|1|HOLD_TO_RUN|1|COAST_ERPM|1600|RESUME_ERPM|1400|MODE|CURRENT_PI|POLE_PAIRS_ASSUMED|7|TARGET_RPM|200|TARGET_ERPM|1400
```

版本或MODE不符时先检查重新构建与烧录日志，暂不转轮。INFO只读，不会启动电机。

## 2. 先运行左轮

1. CH1中位、CH5 OFF、CH6高位，给两只电调上电，等两轮反馈正常且停稳。
2. 发送WHEEL OFF，再发送WHEEL LEFT，必须收到W|OK|LEFT。
3. 保持OFF且CH1回中至少0.5秒，再CH5 ON，向CH1数值增大的方向推住。
4. 先观察约2秒；运行平顺且I36为0，再继续到本次总计约5秒。出现故障、抖动或异响时立即回中并CH5 OFF，本轮结束。
5. CH1回中、CH5 OFF，发送下面两条只读查询，将完整回复复制出来。无需在运动中手动连续发送三次STATUS。

```text
WHEEL SPEED
WHEEL STATUS
```

6. 保存本次回复后发送WHEEL OFF，等两轮停稳。若左轮出现故障，先检查这两条回复，暂不继续换轮重试。

## 3. 再运行右轮

左轮本次没有故障且两轮停稳后，重复上面的流程，仅将WHEEL LEFT改成WHEEL RIGHT。结束后同样复制一条SPEED和一条STATUS。左右统计在各自真正启动时重置，因此开始右轮前要先保存左轮回复。

## 怎样理解新查询

WHEEL STATUS保留原10个字段和原I29至I38通道。

WHEEL SPEED采用字段名称输出，本次统计停机后保留：

| 字段 | 含义 |
| --- | --- |
| LAST_WHEEL | 本次统计属于1左或2右，0表示尚未启动 |
| ACTIVE | 会话活动，停机后为0 |
| TARGET_ERPM / RAMP_ERPM | 固定目标1400 / 当前斜坡目标，停机后斜坡目标清零 |
| FILTER_ERPM / RPM_EST | 所选轮滤波速度大小 / 除以假设7对极的估算rpm；停机后保留最后控制样本，不代表停机后的实时轮速 |
| AT_LIMIT | 当前给定是否达到500mA；停机后为0 |
| IN_BAND | 原始和滤波速度都在1260至1540ERPM且连续至少500ms；停机后为0，不是拨盘就绪许可 |
| RUN_MS | 上次控制调用累计的会话时长ms，不是保护响应时间 |
| PEAK_ERPM | 本次所选轮有效STATUS1的原始绝对ERPM峰值，未滤波；另一轮仍参与保护，但不混入此峰值 |
| BAND_MAX_MS | 达到最终斜坡目标后，原始和滤波速度都在上述区间的最长连续时间ms |
| LIMIT_MS | 控制更新时累计达到500mA给定的时间ms |

这些统计描述软件收到的反馈；不能证明独立机械测速、完整保护时限或6000rpm达标。若PEAK_ERPM低于2000而STATUS故障16，仍需考虑另一轮触发或后续数据覆盖，不能排除故障。

## VOFA自动通道

首档模式共44通道，前39通道保持原顺序。除了I29/I30、I31/I32、I34、I35/I36，还可观察：

| 通道 | 含义 |
| --- | --- |
| I39 | 所选轮斜坡目标ERPM，最终1400 |
| I40 | 所选轮滤波ERPM大小 |
| I41 | 所选轮按7对极估算的rpm |
| I42 | 当前给定达到电流上限 |
| I43 | 当前满足首档速度区间的500ms连续判据 |

正常滑行仍为I34=0、I35=1、I36=0；真正停止I35=0。若一直I42=1但速度很低，说明当前给定已到上限且没有达到目标，先保存回复，不自动提高电流。故障位定义沿用原版本。
