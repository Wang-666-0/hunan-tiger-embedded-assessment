# USART1 电机参数采集步骤

本次沿用第15项遥控器配置，不需要开启十通道。云台板已更新为Cherrycoast4.8.1，接收机改接新板P2上层，见[接收机接线](Cherrycoast4.8.1接收机接线.md)。采集通路是：电脑USB转串口 ↔ USART1 ↔ STM32查询CAN电调。SWD用于烧录；不用它直接访问电机，也不用增加USB-CAN适配器。

## 1. 先确认本次能获取的内容

| 设备 | 本次支持 | 仍需要另外确认 |
| --- | --- | --- |
| DM3507，CAN1 ID2 | MasterID、SlaveID、模式、超时、版本、NPP、Gr、PMAX/VMAX/TMAX、波特率字段等14项 | 机械正方向、零点、软限位、实际停机行为 |
| 两只N630/VESC，CAN2 ID70/71 | 固件与硬件名称、配置极数/传动比、完整电机配置和应用配置原文、实时电气转速/电流/电压等 | 配置极数是否符合实物、电机到摩擦轮的真实传动关系、正方向 |
| C610，CAN2 ID5 | 如果有0x205反馈，记录转子角度、转速及原始转矩反馈 | 拨盘每发累计转子编码器计数、到位容差、堵转限流；无需商品型号 |
| GL60Ⅱ，CAN1 ID1 | 最近CAN原始反馈及帧计数 | 官方GLⅡ手册没有供本工具使用的CAN参数读命令；模式、量程、MasterID等需厂家串口工具/已有配置记录 |

读取VESC不会运行电机检测或更改设置。极数/传动比是电调里保存的配置，可能仍是默认值；不能自动当作实物标定值。`complete=true`只表示本轮DM/VESC查询全部完成，不表示机械标定或整项考核完成。

## 2. 烧录前准备

1. 保留云台板原固件工程或HEX/BIN；若只有实物中的固件，请用现有烧录软件读出Flash备份后再替换。
2. 首次只给云台板和接收机逻辑电源，断开执行器动力；清空发射机构，解除飞行动力，固定好云台。参数采集代码不主动使能电机，但上电前仍应排除电调原有输入或其他控制器的运动命令。
3. 遥控设置保持原样：CH1回中、CH5=OFF；CH6照第15项配置运行许可。采集不需要CH5解锁。
4. 接收机仍用i-BUS SERVO端口：S → 新板P2上层pin4 / PA1，+ → P2 pin5 / 5V，− → P2 pin6 / GND。新板P1是GPIO排针，不接接收机；白色USART4/J7的RX是PC11，当前固件不会接收该脚。

## 3. 烧录本次参数采集固件

已生成的HEX：

```text
D:\Project\27电软正式批考核\16_云台调试\Output\Gimbal_Control\MDK-ARM\build\Gimbal_Control\Gimbal_Control.hex
```

用上一任务的ST-Link/SWD下载方式烧录这个HEX，复位运行。也可打开 `Output/Gimbal_Control/MDK-ARM/Gimbal_Control.code-workspace` 在EIDE中构建并下载，或打开同目录Keil工程。`Scripts/build.ps1`仅编译，不烧录。本次Codex已完成编译，但未替你烧录或打开实物串口。

若EIDE一直开着旧版项目，先在App分组右键“添加文件”加入新增 `app_diagnostics.c`、`dm_diag.c`、`vesc_diag.c` 并保存项目，再执行“eide: 重新构建”；也可接受EIDE自身的项目文件变更重载提示。旧缓存可能自动覆写文件清单，普通“重新加载窗口”不是这个项目重载。直接下载上面的HEX无需重新编译。

本机EIDE 3.27.2的“选项字节配置”不是None下拉项，点击会打开或创建INI；本次无需点击。当前配置引用的INI不存在，下载器不会发送选项字节写入命令。None属于“外部加载算法”字段。若已创建选项字节INI，应先检查是否含有效参数，再继续下载。

## 4. 检查 USART1 必须双向通信

继续使用VOFA原来连接的USB转串口和COM号，115200 / 8N1。

| Comet USART1 | USB转串口 |
| --- | --- |
| T / PA9，板端TX | RXD |
| R / PA10，板端RX | TXD，3.3V TTL信号 |
| G / GND | GND，共地 |

如果以前VOFA只有波形接收，可能只接了板端T→电脑RX；这次还需要电脑TX→板端R才能发送查询。不要把TX接TX，也不要使用RS-232电平。云台板已有供电时，不用再将转串口VCC接入板端V脚。

先用VOFA确认仍能接收 `gimbal:...`，协议FireWater。只依赖原CH1/5/6，输出许可通道12始终为0；CH7..10不需要配置。确认后点击VOFA“关闭串口”，采集工具与VOFA不能同时占用同一COM。

## 5. 运行采集

查询需要相应电调实际通电。确认已烧录采集版后，在现场负责人的供电安排下给待测电调上电，维持CH5=OFF，保留原CAN接线。两条总线当前均为1Mbps，CAN2必须与同总线C610相容。VESC查询回包地址使用240，应确认现场没有其他VESC节点使用此ID；不要为试读直接更改电调波特率。

打开PowerShell，可以从任意目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\Project\27电软正式批考核\16_云台调试\Output\Gimbal_Control\Scripts\capture.ps1"
```

工具会列出COM并提示输入端口，填写VOFA原来使用的那个，例如 `COM11`。本次电脑枚举到COM7和COM11，未连接两者；仅凭名称不能替你确定板端口。

只想先列端口时，在命令后加 `-List`。已确认COM号后也可直接运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\Project\27电软正式批考核\16_云台调试\Output\Gimbal_Control\Scripts\capture.ps1" -Port COM11
```

`COM11`是示例，需替换成实际端口。启动器自动查找Python，当前电脑已在 `Tools/.deps` 安装pyserial3.5。换电脑时需要Python3.10+，缺依赖时启动器显示安装到本工程的具体命令，不自动修改系统Python。

工具先核对固件标识 `GIMBAL_DIAG_1`，保存状态和最近CAN反馈，再依次读取DM的14项及两个VESC各5项。每次只发一笔读请求，没有使能、转速、电流、设零、保存或检测电机命令。一次设备超时记入报告；CAN错误、回复损坏或电脑接收超时会停止后续查询。按Ctrl+C可以中断，工具会尽力取消会话并保存已取得的数据。

## 6. 保存结果，再继续补全代码

默认生成：

```text
16_云台调试/02_过程记录/参数采集_年月日_时分秒/
  参数采集报告.json
  串口原始记录.txt
```

终端会显示绝对路径。把这两个文件保留下来，一起交给Codex检查。报告里应首先看到 `firmware=GIMBAL_DIAG_1`、`motor_enabled=0`；正常遥控连接时 `remote_fresh=1`，CH1约1500、CH5约1000、CH6约2000。CAN计数只证明收到报文，不能单独证明某台电机在线。

VESC完整配置仅在本地官方6.06签名和长度均匹配时解码；6.05或定制固件可能标为未知布局，此时原始HEX仍已保存，后续可按对应源码补解码。不要用6.06默认配置替代未知实机值。

采集结束，工具释放COM并退出DIAG模式。需要观察VOFA时再打开原串口；若中途强制关闭窗口，手动在串口工具发送 `DIAG OFF`加换行，或复位云台板恢复FireWater。

## 常见结果与下一步

| 现象 | 先检查 |
| --- | --- |
| 串口打不开 | VOFA/其他串口软件是否已关闭同一COM；端口是否与原来一致 |
| 仍能收到gimbal，但没有HELLO | 是否烧录本次HEX、电脑TX是否接板端R/PA10、是否共地 |
| DM超时 | 电调是否通电、CAN1接线、SlaveID是否确为2、是否1Mbps；不需要先使能电机 |
| VESC超时 | 节点70/71是否正确、CAN模式是否VESC、共享CAN2是否1Mbps；需要官方工具核对时只读查看，不随意改配置 |
| CAN_FAULT / TX_FAILED | 保存报告，停止反复试读；检查供电、H/L、终端电阻、波特率及总线上的其他节点 |
| BAD_REPLY / UART_FAULT | 保存两份文件，检查线路和固件版本；工具不会把损坏结果当作可用参数 |
| GL没有反馈 | 本工具不会为了刷新反馈发送使能或运动报文；用GL厂家工具只读查看配置 |
| C610没有0x205 | 检查C610供电、CAN2和ID5；最后两字节是保留项，本工具不把它们当温度 |

取得电子参数后，仍需完成GL配置读取、机械方向/零点/限位、摩擦轮转速关系与拨盘步距标定，再补正式驱动和闭环。参数采集不是遥控保护实机验收；正式动力调试仍须先通过该专项。
