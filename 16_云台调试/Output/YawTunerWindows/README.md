# Yaw 调参工作台 Windows 0.2.0

适配本工程 GL60Ⅱ 固定双环 PID 固件的独立 Windows 上位机。提供真实六参回读、72 通道采集、自动正负 30° 阶跃、小范围参数扫描、重复验收和本地数据保存。0.2.0 新增模型 API 接入和 AI 自动调参闭环：基线测试 → 模型建议 → 本地范围校验 → 候选实测 → 固定参数独立验收。

新版验证范围见 [AI 闭环验证记录](AI_VALIDATION.md)。

使用本机 .NET Framework 4.x（最低 4.5，推荐 4.8），无需安装 .NET SDK、Python 或浏览器组件。手动调参、采集和演示可离线运行；真实 AI 建议需要模型 API 和网络。运行目录需要有写入权限。它不烧录、不改写固件，也不把参数写入 Flash；在线参数仅影响当前 RAM 会话。本版本尚未进行真实模型接口及云台实机联调，正式成绩必须由实机证明。

## AI 自动调参快速开始

详细步骤见 [AI 使用教程](AI使用教程.md)。新版运行 `bin\AI\YawTuner.exe`；工作目录中原有的旧版 `bin\YawTuner.exe` 保留，新分发包只包含新版。

1. 在“AI自动调参”页配置 Base URL、API 类型（Responses 或 ChatCompletions）、Model 和 API Key。使用你可调用的模型名称；密钥只在软件填写，不要发送到聊天。
2. 测试模型连接。测试发送合成样例，不操作硬件；真实 API 请求可能计费。
3. 连接串口，按原固件流程人工准备、建立零点并使能，填写负载、供电等工况。
4. 启动 AI 自动调参。默认总预算 24 轮、最多 4 次模型建议，所有参数始终限制在 AI 启动时真实回读参数的全局 ±15% 内。
5. 软件自动完成正负基线、候选实测和比较；候选满足硬条件后另起正负各 5 次独立验收。模型等待期间回零保持并持续监控状态。

模型仅提出单参数候选，执行和成绩判定由本地程序完成。实机独立验收通过后留下通过参数在 RAM；正常未达标结束会回零恢复 AI 启动时参数；停止或异常会请求 OFF，不自动恢复参数或重新使能。默认不记住 API Key，勾选记住后仅使用 Windows DPAPI 对当前用户加密保存。

演示时先连接“演示模式”，再在 AI 页选择“离线脚本演示（非实时 AI）”，使用脚本建议和模拟反馈，不调用真实模型，不证明云台达标。若选择“实时模型接口”，测试和自动流程会调用实际配置的 API，即使云台是模拟源。

## 启动与演示

双击新版 `bin\AI\YawTuner.exe`，默认处于未连接状态。双击 `start-ai-demo.cmd` 或点击界面上的“演示模式”，也可以在 PowerShell 中运行：

```powershell
.\bin\AI\YawTuner.exe --demo
```

演示使用程序内虚拟串口协议源，不打开真实 COM 口。界面和文件明确标注 DEMO；模拟结果仅用于检查软件流程，不能作为实机验收记录。

已有 EXE 可以直接使用。重新编译和运行离线检查使用：

```powershell
.\build.ps1
.\build.ps1 -Test
.\release.ps1
```

`build.ps1` 使用系统 .NET Framework 自带编译器；`release.ps1` 用于生成分发包。运行 EXE 时保留旁边的 `YawTuner.exe.config`。

## 连接和首次检查

1. 在 VOFA 或其他串口工具中断开设备，释放 COM 口；同一串口不能由两个程序同时占用。
2. 选择端口，点击“连接设备”。固定使用 **921600 / 8N1**。连接只请求状态和参数，切换 `YAW VIEW` 并开启 `TELEM ON`；不会下发源码默认六参、建立软件零点或自动使能。
3. 左侧“板端回读”显示当前真实生效的 PKP、PKI、PKD、VKP、VKI、VKD，并保存为本次连接基线。“待写入”是编辑区，不代表已经生效。点击“重新读取”可再次同步。
4. 确认固件版本、固定双环模式、72 列遥测、真实阶跃和考核口径兼容。版本或协议不匹配时阻止试验；不要仅凭串口已连接就开始。
5. 按现有固件和遥控流程人工准备云台、建立零点并使能。上位机不发送 `YAW ON`、`YAW READY` 或 `YAW CLEAR` 来自动解锁或清错。

开始试验时，遥控必须保持新鲜、四杆回中，CH6 摩擦轮关闭、CH7 测试按钮释放、CH8 扳机释放；CH5 置手动或测试活动档，并已通过新的 OFF→活动边沿人工解锁。按现有考核映射：CH5 上档约 1000 为 OFF，中档约 1500 为手动，下档约 2000 为测试；CH6 关闭约 1000，CH7/CH8 释放约 1500。具体就绪判定以板端为准。

每个方向都从软件零位开始。程序先发送 `YAW HOME`，再轮询 `YAW STEP CHECK`，只有 **`CONSOLE_READY=1`** 才发送阶跃。单独 `READY=1` 尚未包含全部控制台遥控门禁。界面会显示当前停在回零、静止等待、命令确认还是等待成绩，超时后停止流程。

## 手动与本地扫描的使用顺序

以下是原有基线、扫描和独立验收按钮的用法；AI 自动流程见前面的快速开始及单独教程。

1. **记录工况。** 填写负载、供电电压、安装方式等，便于比较同一条件下的数据。
2. **做一次基线。** 点击“基线正负阶跃 · 2 轮”，用当前板端六参分别执行 +30°、−30°，每次采集完整 5 秒。
3. **小范围扫描。** 选择一个增益，输入相对于当前参数的百分比偏移，例如 `0, -3, 3`。首版一次只改变一个参数，各偏移绝对值不超过 15%，最多 5 个候选，每个方向重复 1～5 次。程序保存运行前参数、写入候选并回读确认，再逐次回零、检查就绪、阶跃和等待匹配编号的成绩。
4. **查看候选。** 在“试验成绩”中选择一轮，可查看完整结果和该轮曲线；“对比与建议”给出候选比较。“回零并应用选中组 / RAM”会显式应用所选记录的六参并回读，不会自动把最佳一次的参数永久固化。
5. **独立验收。** 确认板端当前六参就是要验收的固定参数，再点击“独立验收 · 10 轮”，正负方向各 5 次。以最差成绩、重复性和完整波形判断，不能只取最好的一次。

使用这三个独立按钮时，基线、扫描和验收正常完成后，程序回到零位，并恢复**该次运行开始前**的六参。手动扫描不会自动留下获胜候选。若要验收某个候选，应先明确应用它，再启动独立验收。AI 自动流程会自行衔接这些步骤，通过独立验收后保留获胜参数。

手动改参使用“回零并写入”；它与“回零并应用选中组”都以真实回读确认结果。板端允许范围如下，所有增益必须是有限、非负数：

| 环路 | Kp | Ki | Kd |
| --- | ---: | ---: | ---: |
| 位置环 | 0～30 | 0～10 | 0～2 |
| 速度环 | 0～0.02 | 0～0.2 | 0～0.001 |

小范围扫描还会额外执行相对变化约束。当前生产固件没有原 180°/s 和 0.1 Nm 业务限幅，力矩仍受协议端点限制；上位机不会修改这些固件保护配置。

## 成绩和曲线如何解释

程序分别保留三个判断，任何一项缺失都不能当作完整通过：

| 判断 | 含义 |
| --- | --- |
| 板端成绩完整 | 对应本轮编号、方向和实际六参，收到有效 DONE 成绩，采集窗口和考核口径匹配；ABORTED 不算完整通过。 |
| 主机波形覆盖 | 独立检查主机接收范围、间隔和板端新反馈时间戳；板端有完整成绩，不代表电脑一定收到了完整波形。 |
| 硬条件通过 | 真实 30° 阶跃，最终进入并持续保持 ±0.2° 的时间 ≤250 ms，超调 ≤0.2°，稳态误差绝对值 ≤0.2°。每项单独判断。 |

板端采集窗口为 5 秒，最后 1 秒计算时间加权稳态误差，并要求这 1 秒始终在 ±0.2° 内。`RESP` 是首次进入误差带的时间；`SETTLE` 是最终进入并保持到窗口末的时间，正式时间判定使用后者。未达到的时间值为 `-1`。程序不以一个综合分数掩盖某项不合格，也不用平滑轨迹替代真实阶跃。

曲线可切换角度/目标、误差/±0.2°、速度/目标速度、力矩请求/反馈；“72 通道”可查看全部原始字段。遥测每 5 ms 发送快照，控制计算周期为 2 ms，Yaw 指令发送周期为 10 ms。I63 是 **32 位板端 CAN 反馈接收毫秒戳**；同一戳的重复快照是正常现象，不能当成独立 CAN 反馈样本。原始快照全部保存，覆盖检查使用新反馈时间戳。

**现有协议没有输出阶跃接受时刻 `t0` 的板端毫秒戳。** 成绩中的 `START` 是起始角度；图表横轴使用主机相对接收时间，不能据此替代板端精确响应时间。主机虽保存命令、应答和接收时间，但不能声称已经同步测得计算、CAN 执行和机械反馈的完整延迟链。温度与反馈间隔用于状态观察，也不等于完成了全部瓶颈测量。

## 停止、故障和恢复

点击红色“停止 / OFF”会取消后续试验并发送 `YAW OFF`。固件中的这个命令还会调用**全系统停止**，影响 Yaw、Pitch、摩擦轮和拨盘，并非只取消电脑任务。Pitch 失能后有负载下落的可能，操作前应按既有机械使用条件支撑负载。

在受监控试验或活动态参数恢复过程中，通信中断、故障、超时、无效数据或保存失败会停止流程并尽力发送 OFF；串口已经断开时不能保证板端收到停止命令，仍需使用现场遥控保护。连接和只读检查发现协议不兼容或解析异常时仅报错并阻止试验，不发送 OFF。故障或取消后不会自动重新使能，也不会为完成试验强制回零。

“恢复连接时基线 / RAM”用于恢复**本次连接建立时回读并保存**的六参，不是源码默认值，也不一定等于最近一次试验的参数。该操作与重新使能分开：恢复 RAM 参数不等于解除板端故障、捕获零点或重新允许输出。健康且仍活动时，先回零再恢复；已失能时只恢复参数，不为此自动使能。若设备断连或回读失败，恢复不能被视为完成，需重新连接并核对真实六参。重连会建立新的连接基线，应从原会话记录找回旧参数。

停止后按固件原有流程检查状态、人工处理故障，并重新执行所需的遥控 OFF→活动解锁。需要建立新的软件零点或人工清错时，沿用已有调试流程。

## 自动保存与导出

连接后创建独立会话目录，路径显示在窗口底部。默认位置为 EXE 旁的 `sessions`，通常是：

```text
bin/AI/sessions/
  HARDWARE_实机/或 DEMO_模拟_非验收/
    时间_唯一编号/
      session.json
      raw.jsonl
      telemetry.csv
      trials/每轮编号.json
      summary.csv
      summary.json
      AI_分析摘要.md
      ai_runs/每次AI运行编号/
        anchor.json
        trace.jsonl
        report.json
```

| 文件 | 内容 |
| --- | --- |
| `session.json` | 会话类型、创建时间、考核定义和遥测列名。 |
| `raw.jsonl` | 按行保存收发方向、主机时间和原始命令/应答/遥测，保留审计依据。 |
| `telemetry.csv` | 主机相对时间、模式及全部 72 列遥测，不只保存图表当前显示的通道。 |
| `trials/*.json` | 单轮实际参数、工况、方向、板端原始成绩、独立判定和波形。 |
| `summary.csv` / `summary.json` | 各轮成绩、完整性、未通过原因及汇总。 |
| `AI_分析摘要.md` | 供模型或人工继续分析的参数与成绩摘要。 |
| `ai_runs/*/anchor.json` | AI 启动时的真实六参、工况和预算。 |
| `ai_runs/*/trace.jsonl` | 模型建议、本地决策、计划与实测结果摘要。 |
| `ai_runs/*/report.json` | 本次 AI 流程状态、是否独立验收通过、最佳候选与已完成计划的结果摘要。中断组的逐轮记录以会话 `trials` 为准。演示不会标为实机通过。 |

数据接收、界面绘图和磁盘写入分开处理。记录自动保存；“导出成绩 / 波形 / AI 摘要”可再复制一份到所选目录。导出不会把模拟数据转换为实机记录。不要在采集过程中删除当前会话目录，或让输出磁盘失去写入权限。

## 当前边界

当前策略是**模型建议单参数候选、由本地完成有界扫描和实测比较**，尚不是贝叶斯优化、系统辨识或独立速度内环整定。`YAW VEL` 在现有协议中用于设置速度环三个增益，不能执行独立速度阶跃。变化范围相对 AI 启动参数固定，不会通过每轮重设基线累计扩大；原本为零的参数默认保持零。

内置 AI 通过配置的 Responses 或 ChatCompletions 接口在两轮试验之间获取建议，不能直接发送电机命令。当前聊天中的模型登录不会自动成为软件的 API 凭据。发送到服务商的是工况和调参成绩摘要；不配置 API Key 仍可使用手动流程、局部扫描和脚本演示。保留的旧版 0.1.0 只有离线摘要导出能力。

本程序当前聚焦 Yaw；Pitch、遥控保护、摩擦轮、拨盘等完整考核项目仍需按各自要求验收。离线测试与演示只能证明软件部分行为，不能证明云台动态指标已经达标。
