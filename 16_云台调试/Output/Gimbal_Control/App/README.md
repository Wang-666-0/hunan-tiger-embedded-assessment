# App 分文件说明

沿用上一考核：业务文件平铺在 App，模块使用配对 .c/.h，统一配置放在 `app_config.h`。main.c保留外设初始化；freertos.c调用 `AppTasks_Create`，业务逻辑通过模块接口运行。

## 已实现模块

| 模块 | 职责与边界 |
| --- | --- |
| ibus | 复用上一任务的32字节帧解析、校验、14路通道与帧间超时 |
| remote_input | UART4 ISR搬运字节、实际接收时刻和故障代次；任务解析，旧队列字节不能恢复许可 |
| remote_mapper | 默认沿用第15项CH1/5/6；可选完整十通道映射；不依赖HAL |
| safety_manager | 新帧OFF→ON解锁、回中检查、100 ms超时、Failsafe、STOP、UART/CAN故障与控制迟到 |
| target_manager | 手动请求、机械6000 rpm请求、单发沿和50 ms连发节拍、回中后±30°阶跃事件 |
| app_logic | 按映射→保护→目标的顺序组合纯C逻辑，便于离线测试 |
| can_frame | 双CAN帧统一结构与11/29位ID、DLC0..8校验 |
| can_bus | 双CAN队列与故障代次；动力发送门禁；独立DM/VESC白名单只读接口及发送取消 |
| dm_diag | DM3507的14项参数读取组帧与回复匹配；不写参数或使能 |
| vesc_diag | VESC固定读命令、单请求分片拼接与CRC16校验；不写配置或控制 |
| app_diagnostics | 1200ms超时、取消、故障隔离、DM MasterID核对、32字节结果交付及最近16种CAN帧 |
| motor_backend | 预留驱动聚合接口，当前健康状态全为0，拒绝执行请求 |
| app_tasks | 四个FreeRTOS业务任务、快照发布和STOP序号 |
| app_console | 唯一UART回调分发、STOP、29通道FireWater与只读采集文本协议 |
| app_fault | 队列/任务/外设启动失败、栈溢出和内存不足交给Error_Handler |

Keil 与 EIDE 均已登记这15个源文件和 App 头文件路径。私有队列留在所属模块；控制任务独占 AppLogic 状态，遥测通过临界区获取快照。

诊断由电脑显式请求触发，上电只监听CAN，不自动发查询。CAN任务独占协议拼接；Console只提交一笔请求并读取结果块。取消、总线错误或1200ms超时会结束查询并撤销挂起发送。两条总线都关闭自动重传，缺ACK时不会持续重发；仲裁丢失也可能造成超时，由用户查明原因后重新采集。读查询不需要遥控解锁，因为不能构造动力命令。

## 关键设计

`operator_armed` 表示遥控动作通过保护检查；`output_allowed` 还要求正式后端就绪与真实关键反馈在线。基础版可以显示前者为1，后者始终为0。CAN1/CAN2为正常模式，硬件ACK仍存在。

故障优先于解锁。重复读取同一个遥控快照不算新OFF/ON；故障前排队的帧、故障同毫秒的帧都不能解锁。解除故障不会补发旧单发/连发事件。事件位只在当前控制周期有效，累计序号用于观察，不是待执行队列。

发射必须具有动力许可及真实的双摩擦轮稳速反馈。基础版不制造假反馈，所以上板不会出现单发事件。离线测试注入就绪条件，检查单发不重复、连发最小50 ms间隔、迟到不追赶和互锁撤销。

阶跃模式下摩擦轮和拨盘请求关闭。CH10先回中，再到一端生成一次事件；从一端直接转到另一端不再触发。`step_delta_deg` 是相对参考角的目标偏移；回中清零，下一阶段由阶跃模块保存参考角和测量跳变时间，不在本模块添加轨迹平滑。

## 后续补全顺序

1. 按实机读取值加入 `gl60_ii`、`dm3507`、`vesc_can`、`c610` 配对模块；核对模式、量程、ID、方向和波特率。
2. 完成 `MotorBackend_OnFrame` 分发和带时间戳反馈；用互斥/临界区发布一致快照，不能直接共享多字段浮点结构。
3. 加入单轴闭环、零点和软限位，再接摩擦轮稳速、拨盘位置步进与堵转保护。
4. 实现各协议已验证的停机报文、驱动通信超时及反馈失效处理；不要简单开放所有锁定态发送。
5. 加入真实阶跃记录、指标计算和前馈，逐阶段验收后再启用动力。
