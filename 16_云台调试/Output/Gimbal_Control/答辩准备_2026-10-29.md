**3. 必须能画出的系统链路**

```text
遥控器 → UART4 DMA/IDLE → 字节队列 → RemoteTask/iBUS 解析
                                            ↓
                         RemoteMapper：通道 → 业务命令
                                            ↓
                       ControlTask：安全许可 + 目标管理
                                            ↓
                         各 Backend：使能、闭环、停止
                                            ↓
                                  CAN → 电调 → 电机
                                            ↑
CAN 接收中断 → 帧队列 → CanTask → 协议解码 → 反馈与控制器状态

ConsoleTask：接收调参命令、查询状态、输出 VOFA 遥测与测试报告
```

分层的理由：协议层处理字节与报文；控制器处理数学和状态；Backend 处理设备会话与实际发送；系统层统一协调遥控、安全和目标。两轴共用 `gimbal_pid` 数学实现，但各自保存独立状态，Pitch 也使用这个名字下的共用接口。

| 任务 | 调度方式 | 优先级 | 职责 |
| --- | --- | --- | --- |
| RemoteTask | 2 ms 周期 | 4 | 取接收队列，解析遥控有效帧 |
| CanTask | 队列阻塞等待，有帧时处理 | 4 | 分发电机反馈，隔离旧故障代次数据 |
| ControlTask | 2 ms 周期 | 3 | 安全判定、业务目标、各电机执行 |
| ConsoleTask | 5 ms 周期 | 2 | 命令、回执、遥测 |

FreeRTOS 的任务优先级数字越大越高；Cortex-M 的中断优先级数字越小越高，两者不能混为一谈。工程 SysTick 配置为 1 kHz，周期任务使用 `vTaskDelayUntil`。CAN 任务的队列等待超时为 2 ms，不代表 CAN 帧固定每 2 ms 到达。

**5. 双环 PID：能解释下面四行，就掌握了讲解主干**

令 `θref` 为目标角度、`θ` 为电机反馈相对角度，`ω̂` 与 `α̂` 为滤波速度、加速度：

```text
位置误差：eθ = θref − θ
位置环：  ωref = Kpθ·eθ + Iθ − Kdθ·ω̂
速度误差：eω = ωref − ω̂
速度环：  τraw = Kpω·eω + Iω − Kdω·α̂ + τg + τbrake
输出：    τcmd = clip(τraw, −τlimit, +τlimit)
```

积分按 `Ki × 误差 × 实际反馈 dt` 更新，且有抗饱和条件。Yaw 的重力与制动附加项为零；Pitch 在力矩层叠加重力与制动。Pitch 当前直接使用最终角度目标，可选轨迹速度入口已从实现移除；原遥测占位保持不变。

需要说清的六点：

- 外环将位置误差转换为速度目标；内环依据速度误差调节协议力矩。位置用 °、速度用 °/s，内环输出按协议 N·m 表示。
- 两个 D 项都对测量量微分：外环减速度项，内环减加速度项。目标阶跃不会直接进入 D 项形成微分冲击。
- 控制任务可以每 2 ms 重新计算 P 项；积分依据反馈序号和接收时间推进。同一帧反馈被重复读取，不会重复累计积分。
- 速度观测来自解环后的位置差分与低通。电机协议原始速度还用于健康、静止及制动一致性检查，两路速度用途不同。
- `α = dt / (T + dt)`；增大滤波时间常数通常降低噪声，也增加滞后。Pitch 用较短速度滤波，目的是减少停车后旧速度估计残留。
- 当前没有外环速度参考截断；总力矩按协议端点 ±10 限幅。±10 是代码协议映射端点，不能直接解读为已经验证的安全持续力矩。

抗饱和的具体实现：内环积分自身限幅，当积分增量会继续加重总力矩饱和时拒绝该增量；外环也检查积分是否继续推向饱和。不能只回答“最后给输出加个限幅”，因为输出限幅本身不能消除积分积累。

**6. Pitch 的三个重点问题**

**为什么要重力补偿？**

Pitch 的负载会产生随角度变化的重力矩。当前模型为 `τg = Kg × cos(θ + θoffset)`，调用 `cosf` 前转换为弧度。角度相对水平定义时，水平姿态附近重力力臂最大，因此使用余弦。Kg 的符号取决于坐标和电机正方向；当前 −0.13 表示这个工程的补偿方向。

它是依据姿态模型预先提供的支撑力矩，减轻反馈积分长期承担静态负载的负担。PID 仍负责模型偏差与扰动。软件零点和物理水平基准不同，必须说明水平标定与偏置的含义。自动准备假设上电姿态已放在确认过的水平机械基准，代码没有接入 IMU 自动判断水平。

**为什么到位后可能回退？**

可从速度滤波滞后、积分支撑不足或释放不合适、重力补偿偏差、惯量与摩擦几方面排查。不要仅凭一条角度曲线断定原因；应同时看目标/实际角度、原始/滤波速度、内外环积分、重力项和最终力矩。

**末段制动是否就是前馈？**

接近目标时，程序根据剩余角度估计允许速度，超过后施加反向阻尼；首次到位后的短时间内也识别实际回退。当前末段窗口为 4°，接近制动力矩上限 0.12，回退抑制上限 0.30，并限制力矩增长率。

虽然代码通过共用的附加力矩入口求和，制动依赖实际位置和速度，本质上包含反馈阻尼；答辩中明确的模型前馈例子应当讲重力补偿。全程轨迹整形已从实现移除，控制目标直接阶跃，与验收要求对应。

**7. 安全机制要用具体时序讲**

正常路径：上电保持安全 OFF → 健康反馈与静止检查 → 建立参考/准备 → 收到新的 OFF 帧 → 回中且满足条件的新 CH5 解锁动作 → 后端使能握手 → 闭环输出。

失联路径：有效遥控帧超时或检测到故障 → 撤销运行许可与请求 → 取消相关待发动力报文并走停止路径 → 建立新的时间/序号屏障 → 通信恢复后仍需新的 OFF 和解锁操作。

关键解释：

- 有数据到达不等于有有效遥控帧；要通过帧头、校验和、通道范围和时效检查。
- 遥控 100 ms 无有效更新会撤权；控制调用间隔超过 10 ms、CAN/串口故障代次变化、执行器故障等也会进入保护。
- 新 OFF 帧必须晚于故障/STOP 屏障。队列里故障前的 OFF 帧不能参与恢复。
- 电机在线、软件已准备、设备已使能和当前输出获准是不同状态；`READY` 不等于立刻带动力。
- 故障判断、许可和提交在临界区内协调，防止中断撤权后旧状态又把许可打开。临界区中没有串口阻塞发送；其最坏执行时间仍值得实测。
- Pitch 失能后不会自动提供重力保持；进行失能或断电验证时按本项目既有机械支撑方式操作。

| 链路 | 当前实现 | 追问重点 |
| --- | --- | --- |
| 遥控 | UART4，115200，iBUS，DMA+IDLE 接收 | 接收事件不是协议帧边界，仍需流式解析与重同步 |
| 调参与遥测 | USART1，921600，8N1，FireWater；遥测配置间隔 5 ms | 接收 DMA，发送仍存在阻塞 HAL 调用，放在较低优先级控制台任务 |
| 双 CAN | 两路 1 Mbps | CAN 时钟 42 MHz / [3 × (1+11+2)] = 1 Mbps |
| Yaw | CAN1 标准帧，命令 ID 1；反馈 ID 0，负载设备 ID 1 | 位置 16 bit，速度/力矩 12 bit；主控做双环 |
| Pitch | CAN1 标准帧，命令/反馈 ID 2，负载设备 ID 2 | 与 Yaw 相似但仍独立校验设备、状态及温度字段 |
| 拨盘 | CAN2，设备 ID 5，反馈 0x205；控制组帧 0x1FF 的首个槽 | 电流为 C610 原始值，当前限制 ±3000，不能说成 ±3000 mA |
| 双摩擦轮 | CAN2，VESC 节点 70/71，使用扩展帧 | 速度反馈为 ERPM，主控 PI 输出受限电流 |

iBUS：32 字节、帧头 `0x20 0x40`、14 通道、通道按小端拼接；末尾校验是前 30 字节之和从 `0xFFFF` 中减去。坏帧滑动寻找下一个起点，未完整帧还检查字节超时。

两轴发出的 MIT 形式控制帧把电调位置/速度增益置零，发送主控算出的力矩，所以不能把 MCU 内部的六个 PID 参数解释成“直接写给电调的 MIT Kp/Kd”。

DMA 降低逐字节接收中断负担；IDLE 提供一批新字节的接收事件。CAN 接收中断保留接收时间戳并入队，协议解析与控制状态更新交给任务。队列溢出或总线错误会记录故障代次，避免悄悄丢数据后继续使用旧状态。

若问串口带宽：921600、8N1 理论上约 92160 字节/秒；想持续 200 帧/秒，平均每帧连同其他输出只有约 461 字节预算。5 ms 是配置节拍，实际帧率、帧长和任务耗时需要测量，不能仅看宏值下结论。

**10. 摩擦轮与拨盘：不能只会讲云台**

摩擦轮：左右轮独立速度 PI，目标有爬升，观测有滤波，电流有限幅和抗饱和，并有温度、反馈时效和超速保护。当前每侧命令上限为 2000 mA，速度环周期 20 ms。

工程按 7 对极、1:1 直驱换算：`机械 rpm = ERPM / 7`，所以 6000 rpm 对应 42000 ERPM。7 对极是当前配置假设，需要与实物一致。斜坡有助于减少突变，PI 避免直接微分放大速度噪声；若没有噪声测量，就用实际运行观察描述，不报未经测量的降噪分贝数。

拨盘：输出轴每发 40°，传动比 35.68，方向 −1；位置 P=10，速度 PI=2/8，控制与命令周期 2 ms。单发使用位置预测、停车距离限速与减速积分释放，目的在于减少终点超调与往复修正。

20 Hz 换算必须会算：

```text
请求周期 = 1 / 20 Hz = 50 ms
输出轴平均速度 = 40° × 20 = 800°/s = 133.33 rpm
转子平均速度 = 133.33 × 35.68 ≈ 4757.33 rpm
```

连发每 50 ms 推进一次目标，2 ms 反馈闭环持续执行。轻微调度迟到保持节拍；明显迟到不突发补齐漏掉的请求。实际 20 Hz 要看电机越过各步边界的完成记录、计数与时间；实弹出弹频率还需要相应的外部观测。单发完成时间也不能直接当作“每 40°都在 ±0.2° 内稳定”的时间。

拨盘编码器为 8192 计数/圈，解环后累计转子角度，再按传动比换算输出轴角度。最短角差法要求采样间运动没有产生半圈歧义；当前有结合转速和时间间隔的跳变/半圈检查，不能声称严重丢帧时仍能猜回丢掉的圈数。

**14. 高频追问：先练会这些短答**

| 问题 | 回答要点 |
| --- | --- |
| 为什么不用单位置环？ | 串级结构把位置跟踪与速度调节分开，外环给速度、内环给力矩，便于处理运动阻尼与扰动；稳定性仍需参数设计和实测。 |
| 这是位置式 PID 还是增量式 PID？ | 当前直接用 P、积分状态和测量 D 求控制输出，属于位置式表达；积分采用离散累加，不是累加 Δu 的增量式。 |
| PID 三项各有什么作用？ | P 对当前误差响应，I 补偿持续偏差，D 提供对运动变化的阻尼；分别对应响应、静差、超调/噪声的权衡。 |
| 怎样调参？ | 先确认方向、单位、反馈时效、零点与限位；先内环后外环，分离 P/I/D 作用，一次只改一类变量，用相同测试条件比较完整指标。具体过程用自己的真实调试记录说明。 |
| 为什么用差分速度而非只用电调速度？ | 当前速度协议按 ±200 rad/s、12 bit 映射，量化步距约 5.6°/s；位置协议量化更细，结合实际 dt 差分与滤波形成速度估计。差分同样会放大量化噪声，需要滤波。这里是协议量化分辨率，不是实测传感器精度。 |
| 为什么不把滤波开得很强？ | 噪声减小的同时滞后增加，停车后估计可能仍显示较大速度，影响制动与闭环判断。 |
| 为什么不让 D 对误差微分？ | 目标阶跃会让误差突然变化，带来 D 冲击；当前 D 作用于测量，目标变化不直接进入微分。 |
| 输出已经限幅，为何还要抗积分饱和？ | 饱和时执行器无法提供更多输出，积分继续累积会拖延恢复并增加超调；要限制/拒绝继续加重饱和的积分增量。 |
| 为什么积分 dt 不固定写 0.002？ | CAN 反馈异步到达，有抖动与重复读取；按反馈序号和时间推进，才能避免旧反馈重复积分。 |
| 为什么 Pitch 用余弦前馈？ | 相对水平角下的重力力臂按余弦变化，Kg 和水平偏置对应本机构与坐标方向。 |
| 重力补偿和 I 项会不会冲突？ | 前馈承担已知静态负载，积分补偿剩余误差；标定不准或切换不当会改变支撑状态，需要观察分项输出。 |
| CAN 给的是位置还是力矩？ | 两轴主控算串级 PID，电调帧内位置/速度增益置零，发送协议力矩；拨盘发原始电流，摩擦轮发受限电流，不能混说。 |
| CAN 接收为什么使用队列？ | 中断保存报文与时间戳并快速返回，任务解析与更新控制状态；队列溢出触发故障路径。 |
| DMA+IDLE 是否就解决了粘包/拆包？ | 它提供字节批次，不定义 iBUS 帧；仍靠协议帧头、长度、校验与滑动重同步。 |
| 怎么处理角度跨圈？ | 对相邻角差按周期修正后累计，再减软件参考；同时检查帧间隔与运动边界，避免把丢帧跳变当正常跨圈。 |
| 为什么多任务不会互相踩状态？ | 队列交接、临界区快照和控制/提交协调；`volatile` 只影响编译器访问，不能保证整个结构体快照一致。 |
| 临界区会不会影响实时性？ | 会屏蔽受 FreeRTOS 管理的部分中断，所以范围和执行时间要受控。当前无串口阻塞发送，但应测最坏控制耗时与中断延迟。 |
| 2 ms 任务是否证明稳定达到 500 Hz？ | 只表示配置节拍；要看实际控制 gap、CAN 提交/反馈间隔。Yaw 命令本身设置为 10 ms。 |
| 遥控恢复为什么不直接继续？ | 故障撤权建立屏障，必须收到屏障后的新 OFF，再人工解锁，防止旧命令和异常恢复导致突然动作。 |
| 单发为什么还会越过目标？ | 惯量、延迟、剩余积分和减速能力使到达位置不等于停住；当前用预测、停车距离限速与积分释放改善。 |
| 20 Hz 怎样证明？ | 50 ms 是请求节拍；需要实际完成计数与时间，若论证出弹还需对应出弹观测。 |
| 超调 0.2 是 0.2% 吗？ | 当前上限为 0.2°；30°阶跃对应约 0.667%。报告也提供百分比，但阈值不能混用。 |
| 首次入带 200 ms，为什么 PASS=0？ | 可能之后离带、最终稳定超时、超调超限、稳态数据无效，或测量被中止；要逐项看完整报告。 |
| 阶跃记录为什么等 5 s？ | 要观察是否再次离带并统计最后 1 s 稳态误差，不只截取前段快速响应。 |
| 有没有 IMU 稳向或自瞄？ | 当前阅读的闭环路径是电机编码器反馈；IMU、视觉目标接入属于后续扩展，需要新的坐标、时间同步与闭环验证。 |
| 离线测试证明了什么？ | ARM GCC 编译真实 C 代码，在 Unicorn 和 HAL/RTOS 替身下检查逻辑、边界、协议及状态机；不证明实机惯量、真实时延、实际射频或稳定性能。 |
