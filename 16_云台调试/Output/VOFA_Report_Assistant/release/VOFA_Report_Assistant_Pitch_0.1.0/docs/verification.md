# 验证记录

验证环境：本机 VOFA+ 1.3.10，Qt 5.14.2、x64、FireWater；测试运行于独立副本和独立 `rptap` 配置，不替换原 VOFA 可执行文件。

## 原生模拟接收

回环 TCP 测试客户端使用 VOFA 自带的 `DebugClient` 与同一 `DataHub` / FireWater 解析链路。插件监听原接收文本框的 `textChanged`，在 Qt 同轮更新完成后，只读比较有上限的文档快照。没有读取会消耗队列的 `text_buffer.text`，没有修改原接收文档。

- 400 条 `pitch:` 数值帧：波形端 `head=400`，末值 `[400,2,3]`；助手过滤恰好 400 条。
- `PITCH CHECK`：`BUSY` 与终结报告正确收集为两行，期间插入遥测及 13 条 `R|RX`。
- 分成两个传输块的 `P|STATUS|...`：保留为一行，没有拼入其他消息。
- 数据流停止后单独返回的 `PITCH PID`：完整收尾，不需下一条遥测“推出来”。
- 两份报告均完成，其他有效状态文字逐条保留；检测缺口 0、淘汰 0。
- QML 在真实 Qt 宿主加载，界面可见，无插件 QML 加载错误；自身历史文件保存成功。

证据摘要：`validation/native-final-result.json`。这是本机模拟接收验证，不是单片机串口收发、USB 连续运行或 200 Hz 实机性能验收。Windows 定时器实际间隔可能长于测试设定的 5 ms；200 Hz 等效数据另由离线测试覆盖。

## 离线与安装

- 报告引擎：54 场景、2372 断言，包括逐字分包、200 Hz 等效穿插、迟到回复、同格式歧义、容量和损坏历史。
- 桥接：35 场景，包含原生滚动快照重放、裁剪、协议识别、尾段完成、接入撤销、文件路径约束。
- 界面：12 场景，覆盖发送前建档、失败解除等待、单条等待、阅读位置、六个默认命令演示、快捷命令。
- 安装脚本：在假宿主目录验证新装、升级、保留历史、未知目录拒绝、修改文件拒绝和归档卸载。

## 原布局保护

安装前备份全部原 widgets 文件，以及已有的 config/tabviews/cmds 文件。SHA256 清单位于本工作包 `validation/preinstall-existing-files.json`；备份位置记录在 `validation/backup-path.txt`。安装只写独立的 `plugins/widgets/report_assistant`，不覆盖原控件和布局文件，不自动重启、连接或发送命令。

**安装已完成，安装后核对 76 个原文件：修改 0 个、缺失 0 个。** 记录位于 `validation/installed-preservation-check.json`。未自动往现有画布添加控件；下次正常重启后，可在新标签页手动加入。

完整原文件清单、旧配置和备份仅留在本机开发目录，不放进发行压缩包。

## 实用限制

1. 接收依赖 VOFA 内部 QML 引用，其他版本需重新验证。仅明确识别当前 FireWater 后才启用。
2. 显示文档是有界缓存，不是串口抓包。清空、隐藏 RX、切换 HEX 或较长 UI 阻塞可能丢失文字；检测到时报告标记不完整。
3. 固件未加入请求编号。`RESULT/GUARD` 等同格式主动消息标为候选，等待结束后显示“归属待确认”。
4. 最近 100 份报告另有总字符和单报告上限；“保留所有非遥测”指分类时不静默过滤未知文字，并不表示无限存储。
5. 真实串口发送和机械动作未测试。默认按钮只查询，自动重发、自动改参、自动使能均未加入。
